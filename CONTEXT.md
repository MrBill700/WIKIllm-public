# Context

## Terms

**fleet** -- the wikis created from this template that sync tooling from it. **FLEET-SYNCED** = a file overwritten by `scripts/sync_from_template.py --apply`; improve it in the template, never locally.

**claim audit** -- the periodic check that sampled wiki claims still say what their cited sources say: `scripts/audit_claims.py` draws a risk-weighted sample, and the `claim-audit` workflow reads every sampled claim with a panel and escalates dissent to an arbiter.

**lens** -- one narrow question a panel reader answers about a claim. Three lenses: `wording` (quotation and paraphrase fidelity -- degree words, modals, hedges, splices), `scope` (does the cited source cover this clause at the breadth claimed; attribution; over-characterization of what the source says), `numbers` (figures, dates, units, periods, rank words, and a definition applied across every period or arm). The scope lens also owns currency -- whether a later source or vault position supersedes the claim (STALE).

**audit scope** -- the claim audit judges ONE question: does the cited source support what the page asserts about it. Whether a claim fits, supports or contradicts the vault's own positions and plans is deliberately out of scope: that is an argument question for a human, not a citation-faithfulness question. A claim comparing a source to a vault position is still judged on whether the source supports that comparison.

**panel** -- the three independent Sonnet readers, one per lens, run on EVERY sampled claim. Readers never see each other's work. Each returns a verdict (FAITHFUL / DRIFTED / UNSUPPORTED / STALE), a required `needs_arbiter` flag with a reason (a suspicion outside its lens, or a lens check it could not complete), and `primary_kind` (text / image-or-chart / absent). The panel is not a vote: a 2-1 majority never outweighs a dissent.

**escalation** -- sending a claim to the arbiter. It happens when any lens says non-FAITHFUL, any lens sets `needs_arbiter`, any lens could not open the primary (`primary_kind: absent`), or the script sees an image or absent raw pointer. A lens reading a chart (`image-or-chart`) is recorded but does not escalate by itself.

**certainty / severity** -- the arbiter's two extra rulings. `certainty`: `clear` (any careful reader of the primary agrees) or `borderline` (careful readers could reasonably split). `severity`: `material` (a reader acting on the claim would believe something the source does not support), `minor` (imprecise, not misleading), `none`. Borderline drift is never a hit -- it is a `split` for a human. Severity is advisory: it is counted (`material`) but gates nothing. The reasons are recorded per row in `escalation`.

**arbiter** -- the Opus reader at high effort, the only one that emits `final_verdict`. It re-reads everything with all three panel analyses as evidence, not votes. It writes the one proposed fix and rules `fix_ok`.

**spot-check** -- one unanimously cleared claim per run (deterministic pick from the seed) re-read by the arbiter with a find-what-all-three-missed brief. Reported in `spot_check` as agree / MISS, so a shared panel blind spot becomes a measured rate.

**hit** -- an adjudicated non-FAITHFUL claim confirmed by two readers on the same finding: the arbiter upheld a lens that itself ruled non-FAITHFUL or raised a flag. Hits are what the audit is counting.

**cleared** -- an escalated row the arbiter ruled FAITHFUL: the dissent or flag did not survive. Nothing to fix. Counted apart from `hits` so the buckets partition the run -- `hits + cleared + split + unconfirmed + skipped_faithful == n`, asserted in script.

**skipped_faithful** -- a row the panel cleared unanimously on a text primary with no flag (plus a spot-checked clear the arbiter agreed with). Nothing to fix.

**split** -- a row where drift rests on one reader against the rest. `arbiter-only`: the arbiter ruled non-FAITHFUL but upheld no lens that raised the finding (escalated only by an image/absent primary or a missing lens result, or it found something different from what the lenses raised). `spot-check-miss`: the arbiter found drift in a unanimous clear. `borderline`: the arbiter found drift but judged it a call careful readers could split on. `fix_ok` is forced false, the row is excluded from `hits`, and it is never auto-applied -- a human resolves it.

**unconfirmed** -- a row with no adjudicated result: the arbiter returned nothing (`arbiter-failed`), or all three panel readers returned nothing (`panel-failed`). Fails closed -- `fix_ok` false, never applied, named in the audit log entry.

**fix_ok** -- whether the arbiter's proposed fix is safe to apply exactly as written (no spliced quote, wrong negative, over-attribution, status error, broken surrounding sentence). Only a hit can carry `fix_ok: true`; the calling session applies a fix only on a true.

**replay** -- running the workflow on a fixed queue (`args.claims`) against a snapshot tree (`args.root`, `args.raw_root`), so a variant can be benchmarked on a labeled sample instead of whatever `audit_claims.py` draws today.

**machine-verifiable** -- the autonomy boundary of the `wiki-maintenance` pass: a fix for which a script or a count establishes an exact span, a unique replacement, and a verifiable postcondition. The proof is what qualifies it, not the class it belongs to. Content adjectives -- "stub", "complete", "ingested", "stale claim", "wrong anchor" -- are judgment, not machine state, unless a narrower machine contract covers the specific case; a closed vocabulary defined in `_meta/fleet-conventions.md` is such a contract, an open prose field never is. A change that is merely *detectable* is not machine-verifiable: a non-resolving wikilink is detected mechanically, but the correct repair usually is not.

**edit-deny set (gate 1)** -- the files a vault forbids the `wiki-maintenance` pass to edit at all, resolved in code by `scripts/maintenance_preflight.py` (`edit_deny`) and reported on every run: `wiki/log.md` by path rule, plus any page under `wiki/` or `_meta/` carrying `append_only: true` in frontmatter (the `tracker_page` mechanism, so a vault designates its own history files without a template change), plus any page the gate could not read -- an unknown flag state is not a false one, so it fails closed into `paths` rather than being merely warned about. What is denied is **modifying an existing byte**; appending the run's single close-out entry to `log.md` is not a repair and is not denied. The separation from **machine-verifiable** is the whole point: machine-verifiable answers *can this edit be proven*, the deny set answers *may this file be edited at all*, and a proof is no answer to the second question. An earlier version conflated them, so only the first had teeth (regression R81). The set is advisory to the gate -- it never makes a vault `ready: false` -- and it is never silently empty: when nothing resolves, `edit_deny.note` says so, because an empty section reads as protection that is not there. Findings in a denied file are parked **with their count**, not suppressed into a clean zero.

**park** -- to record a finding for a human instead of acting on it, with enough evidence that they can decide without re-deriving it. The destination is routed, never fixed: decided work that just needs finishing goes to `_meta/open-loops.md` (present fleet-wide); an open question goes to the vault's **question tracker** if it has one, otherwise to `_meta/open-loops.md` marked as needing a human; a tooling defect goes to a fleet-repo issue. A parked item carries a **stable key** -- scanner, rule, normalized path, line or claim id -- so a later run updates it rather than re-appending it.

**question tracker** -- the one page where a vault's open questions for a human go, resolved by `scripts/maintenance_preflight.py` (`question_tracker`, with `question_tracker_source`). Legacy first: `_meta/open-questions.md`, then `_meta/for-reviewer.md`, each only when it exists AND the vault's CLAUDE.md names it (a bare filename is a guess; the mention confirms it). Only when neither resolves: exactly one page under `wiki/` or `_meta/` carrying `question_tracker: true` as a top-level frontmatter key with the exact value `true` -- the flag is self-authenticating and needs no CLAUDE.md mention. `question_tracker: true` is an explicit vault-local fallback selector used only when the legacy `_meta` tracker is absent; it does not override `_meta/open-questions.md` or `_meta/for-reviewer.md`. Selection fails closed: two flagged pages, any page the scan could not read, or any top-level `question_tracker:` key line that is not the one canonical `question_tracker: true|false` line (ambiguous -- the gate proves one shape rather than parsing YAML), or any page whose frontmatter is not plain block YAML at column 0 (flow/JSON can nest or escape the key; YAML-invalid characters; U+0085/U+2028/U+2029, which are valid YAML but outside the selector's accepted subset), or a flagged page whose own frontmatter is not simple (one-line plain values and lists only -- nothing that can span lines) leave the tracker unresolved -- unknown uniqueness is not uniqueness (regression R189). Prose that merely quotes `question_tracker: true` inside a value is not a key line and is harmless. Distinct from `tracker_page: true`, which only says "open markers here are expected" (check_stale B2) and is carried by project pages too.

**cause bucket** -- in `wiki-maintenance --triage`, a group of findings sharing one root cause (a renamed directory, a citation idiom this vault never adopted, one bad template) rather than one location. Buckets are formed only after the standing exclusions -- the resolved **edit-deny set** (`log.md` history and any `append_only: true` page), generated pages, intentional unresolved nodes -- because the largest raw group in a neglected vault is frequently the one that must not be touched at all.

**operational state** -- the rollback data a mutating tool keeps about its own runs (for `fix_wikilinks.py --alias-only`: the dry-run manifest, the apply log, and the original bytes of every page it rewrote). It is not vault content and not a disaster-recovery backup; its job is to make an interrupted or unwanted run exactly undoable, on the machine that ran it. It lives in a **state directory** outside the vault and outside any sync service -- default `%LOCALAPPDATA%\WIKIllm\<tool>\<vault-folder-name>-<hash8>`, override `--state-dir` -- because a synced vault holds files open for upload and a high-churn journal written there fails (regression R157, `WinError 5`). A vault's state is keyed by its resolved path, so a moved vault does not inherit its old runs; **state rebind** is the explicit operation that attaches a vanished path's state to the new path (same folder name is only ever a warning, never identity). Legacy in-vault state (`.alias-fix-backup/`, `_meta/alias-fix-manifest.json`) predates this rule.

**run lock** -- the one-per-vault exclusive marker through which `fix_wikilinks.py` operations that can mutate vault pages or shared operational state serialize -- each `--alias-only` state writer (regression R161) and the backtick-mode `--apply` (regression R168) -- for their whole duration: one lock-participating fix_wikilinks writer per vault. External editors (a human, Obsidian, sync, other tools) are outside that guarantee (backtick-mode's own overwrite risk: regression R172). A run that cannot reach it (LOCALAPPDATA unset, Microsoft Store Python) refuses to write rather than writing unlocked. It lives in the vault's DEFAULT state directory whatever `--state-dir` the run uses (keyed by path, like the state; a conservative same-folder-name sibling-lock check covers other path spellings of one vault -- physical identity is not the key), and is created complete in one atomic step, recording its holder (unique lock id, pid, that process's creation time). A **stale lock** is one whose holder is provably gone (pid absent, or alive with a different creation time); only a stale lock may be broken, and only on explicit request -- an unprovable holder counts as alive. On Windows a break judges and deletes the same lock file through one exclusive handle, so it cannot delete a live or replacement lock that it did not judge stale (regression R170, ADR-0008); off Windows `--break-lock` refuses and recovery is by hand.
