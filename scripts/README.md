# scripts/

> **Don't read this to find out what's available — run `python scripts/help.py`.**
> It generates the map from the scripts' own docstrings and argparse definitions, so it
> is always current; this README can drift, and eventually will. `help.py <name>` for one
> script (a prefix is enough: `help.py audit`), `--full` for every flag, `--recipes` for
> the common command sequences. Use this file for the *why* and the prose; use `help.py`
> for the *what* and the flags.

Automation for the wiki. All Python 3, standard library only (two exceptions: `suggest_links.py` needs `networkx`, and `screen_capture.ps1 -WindowTitle "Reader window title"` is Windows PowerShell -- the one non-Python tool). Run from the repo root (paths are resolved relative to it). Pages generated by a script carry `auto_generated: true` in frontmatter — don't hand-edit those; they're overwritten on the next run. Pages this vault treats as append-only history carry `append_only: true` -- `maintenance_preflight.py` resolves them (plus `wiki/log.md`, always) into the edit-deny set the `/wiki-maintenance` pass must not repair, however provable the repair (regression R81).

Two rules that apply to every script here:

- **These scripts come from the WIKIllm template** and are kept in sync with it (`sync_from_template.py`, below). Improve them in the template first, then re-sync — local edits get overwritten by the next sync. Topic-specific scripts (a data monitor, a report generator) are instance-owned and never synced.
- **Never truncate their output with `| head` or `| Select-Object -First N`** — an early-closed pipe kills the interpreter mid-print and reports a false failure (exit 255 under PowerShell). The scanners take `--summary` instead; if a summary count is nonzero, re-run without the flag for detail.

## check_raw.py — change detection for `raw/`

Computes SHA-256 of every file in `raw/`, compares to a stored baseline in `_meta/raw-hashes.json`, and reports added / modified / removed / unchanged.

**Why:** sources get added or quietly edited between sessions, and silent changes slip past `ls` timestamps and memory. The baseline makes detection deterministic.

```
python scripts/check_raw.py                       # report changes (does NOT update baseline)
python scripts/check_raw.py --summary             # counts + names (+ rewrite annotations; no size/mtime detail)
python scripts/check_raw.py --init                # first-time baseline init
python scripts/check_raw.py --accept "foo.pdf"    # accept just one file (multi-source workflow)
python scripts/check_raw.py --accept a.pdf b.pdf  # accept several specific files
python scripts/check_raw.py --accept a.pdf --accept b.pdf  # same -- repeated flags accumulate
python scripts/check_raw.py --accept-all          # accept ALL detected changes (single-source workflow)
python scripts/check_raw.py --duplicates          # report byte-identical files, grouped, largest first (read-only)
```

`--duplicates` exists because name-pattern eyeballing misses real pairs (an 87 MB dup had unrelated names, regression R22) and the scan already hashes everything. It reports and totals; it never deletes -- which copy is canonical needs judgement (keep the name your `log.md`/ledger already cites).

**Line-ending-rewrite annotation (regression R54):** a MODIFIED text file that is
byte-identical to its baseline after CRLF<->LF normalization gets flagged -- a `note:`
line in the detail report, a separate `line-endings-only rewrites:` line in `--summary`
(filenames in the main list stay verbatim, so they remain safe to copy into `--accept`).
The check is **hash-definitive within its scope, not a size heuristic**: the current
bytes are re-hashed with endings converted and compared to the baseline hash, so a
flagged file's *content* is proven unchanged. Scope: allowlisted text extensions only
(binaries -- including NUL-free ones like some PDFs -- never get the hint), and only
uniform-ending reconstructions are attempted, so mixed-ending rewrites and equal-size
changes are never matched (uniform candidates cannot hash-match at equal size). The file
still reports MODIFIED and still needs an explicit accept -- and since `raw/` is
immutable by contract, a pure rewrite means something wrote to the inbox; identify what
before re-accepting. The annotation also degrades silently (no note) for files over
20 MB, NUL-containing content, transient read errors, and files that changed again
mid-scan -- absence of the note is NOT evidence of a real content change (the module
docstring carries the authoritative degrade list). Runs in every mode **including
`--accept-all`**: the bulk accept overwrites the baseline hash (the hint's only input),
so that run is the last chance to notice a recurring inbox writer.

**Derived-render warning (regression R72):** an ADDED file that looks like an agent's render
of a document already in `raw/` gets an extra line under the ADDED block, in every mode:
`DERIVED RENDER? <path> (beside <source>) -- agent output does not belong in raw/; move to
a temp dir or --accept deliberately`. Deliberately narrow -- it fires only when (1) an
added `.png`/`.jpg`/`.jpeg`/`.txt`/`.md` shares its stem with a `.pdf`/`.epub` in the same
directory (`foo.pdf` + `foo.txt`), or (2) an added image is named `pNNN` (`p314.png`) in a
directory holding exactly one PDF (names and extensions compared case-insensitively). A
hand-written companion note named after its PDF (`paper.md` beside `paper.pdf`) also
matches rule 1 -- that is the accepted cost of catching `pdftotext`-style dumps; the
warning asks for a deliberate accept, nothing more. ebook reader capture runs (`page_NNN.png` beside
`run-manifest.json`, no PDF) and provenance notes (`PROVENANCE.md`) match neither rule;
treating every file in a 1,734-file multi-vault test corpus as ADDED flagged 0. A
**warning only**: it never blocks or changes `--accept`, since a render could in principle
be the only copy of something -- that is a human call.

Acceptance is split into two explicit modes on purpose: bare `--accept` (no filenames) is **invalid** — it used to mean "accept everything," which collided with empty shell-splat and caused silent over-acceptance. Pass filenames, or `--accept-all`. If you don't accept, the baseline stays put and the next run reports the same diff (intentional — prevents losing track of "I haven't dealt with this yet").

## lint.py — wiki health-check

Walks `wiki/` + `_meta/` + `CLAUDE.md`, parses every `[[wikilink]]`, and reports:

- **Broken links** -- target resolves to no `.md` in the vault. The most useful signal. Resolution is by basename, case-insensitive; a target matched only through a page's frontmatter `aliases:` is not broken but is not healthy either -- it goes to ALIAS-ONLY below. (This bullet used to call alias resolution "Obsidian-faithful". It is not: Obsidian does NOT open a page from a bare `[[alias]]` -- the link is grey and clicking it creates a new empty note, regression R151, click test 2026-09-29.) Attachment embeds (`![[chart.png]]`) are resolved against the vault's non-`.md` asset inventory (including `raw/`). Output is grouped by distinct target with counts (`x90 [[Double-digging]] (src +89 more)`), so mass-repeated stub links read as one line.
- **Alias-only links** (regression R151) -- targets that resolve only through another page's frontmatter `aliases:` (e.g. `[[Soil Acidity]]` where the page is `acidity-notes.md` carrying `aliases: [Soil Acidity]`). Obsidian shows these grey and does not follow them, so they earn **no inbound credit** -- their intended page can surface as an orphan -- and they are neither counted as broken nor as healthy. When a real basename file and an alias holder share the name, the link is canonical and only the basename file is credited (Obsidian opens that one). The same holds when that basename file is off lint's inventory -- any `.md` outside dot-directories, `raw/` and `templates/` included: Obsidian opens it, so the link is canonical (and credits nothing on the inventory); the vault-wide walk is `_wikilib.vault_md_basenames()`, passed to `link_kind()`, so any caller gets lint's answer. Known asymmetry, pre-existing (it predates R151): a link to a page outside lint's inventory (`raw/`, `templates/`) is BROKEN unless some page also carries its name as an alias, in which case it is treated as canonical (Obsidian opens the file) -- so an unrelated alias can move such a link out of BROKEN; making BROKEN apply the vault-wide basename rule too is a follow-up beside the dotted-name mangling and R150 cases, kept out of R151 so BROKEN stays byte-stable for BOM-free pages. Pages are read BOM-aware (utf-8-sig), so a BOM before `---` does not hide a holder's aliases -- and, the one exception to "only ALIAS-ONLY moves": a BOM-prefixed page's frontmatter is now seen everywhere, so a BOM-prefixed `_meta/` `auto_generated` page is now dropped from the file set and a BOM-prefixed alias holder's links move from BROKEN to ALIAS-ONLY. ALL FILES, BROKEN and ORPHANS can therefore shift in a vault holding BOM-prefixed pages (pinned in `test_lint_alias_only.py` BOM1: pre-alias-only 3/1/1 -> 2/0/0; one large vault has none, others are unmeasured). Count line, printed right after Broken links: `=== ALIAS-ONLY LINKS (resolve only via frontmatter aliases -- grey in Obsidian, regression R151) === N (T distinct targets)`; the full report lists the top 200 targets grouped like Broken links. Until this section landed, lint counted these as resolved: over 90% of one large vault's lint-resolved links were alias-only -- health the human could not see. The remedy is `fix_wikilinks.py --alias-only` (below). `wiki/log.md` hits are counted here too but never rewritten (append-only), so a residue there is the documented exception, not debt. `maintenance_preflight.py` reads the line as optional `alias_only_links` / `alias_only_link_targets` (null on an older lint = not measured, never a blocker). The inventory walk and the per-link verdict (ghost -> `#` -> attachment extension -> resolve -> canonical / alias-only -> cross-vault -> broken) live in `_wikilib.lint_inventory()` / `lint_link_kind()` -- moved there unchanged so `fix_wikilinks.py` can predict lint's verdict on every link it rewrites (full lint output byte-identical before/after the move on a large-vault copy, pre- and post-fix).
- **Cross-vault links** -- targets containing `../` that fail basename match are verified against the filesystem relative to the linking file; those that exist on disk (e.g. a sibling vault's page) report here as verified instead of broken. Basename match always runs first, so wrong-depth links whose last segment names a local page never reach this section -- the next one catches them.
- **Relative-depth links** (regression R76) -- every target with a `../` segment is resolved on disk relative to the linking file (as written, then with `.md`), independent of basename matching; the ones that exist nowhere are listed per (file, target) with two markers: `escapes vault` / `inside vault`, and `basename-rescued` (Obsidian still opens *some* page, so no other section shows it -- the sample-vault-e `start-here` case) / `also broken` (already counted under Broken links -- or, when the last segment matches only a frontmatter alias, under Alias-only links: an alias match is not a rescue, regression R151, since Obsidian opens nothing for it). Count line: `=== RELATIVE-DEPTH LINKS (../ that resolve to nothing on disk) === N (escape vault E, inside vault I; basename-rescued R, also broken B)`. Purely additive: no other count moves. Trigger is the `../` segment only -- any-`/` would flag thousands of ordinary `[[concepts/foo]]` links. `maintenance_preflight.py` reads the count as an optional `relative_depth_links` (absent on an older lint = not a blocker).
- **Orphans** -- pages with zero inbound wikilinks (expected: `log.md`). Only links Obsidian can follow count as inbound; alias-only links do not (regression R151). Anything else suggests a missing `index.md` entry or a forgotten cross-reference.
- **Ghost / placeholder links** — `[[date]]`, `[[published]]` left by web clippers.
- **Inbound-count hubs** — sanity check that the high-traffic pages are the ones you expect.
- **Locator hygiene** -- source-citation anchor coverage plus broken / suspect heading anchors, delegated to `audit_claims.iter_claim_lines()` and `suggest_anchors.check_anchors_full()`. The section describes the **cwd vault**, like every other section: lint re-points the sibling scripts at cwd via `suggest_anchors.set_root()` (which cascades to `audit_claims.set_root()`) before scanning (regression R101 -- before that, a template / worktree copy run from a vault root printed the vault's link inventory beside the *script repo's* locator numbers in one report), and prints `  root: <path>` under the header, in `--summary` too, so a pasted report always says which tree its numbers describe. A cwd with no `wiki/` (or a sibling `audit_claims.py` / `suggest_anchors.py` older than regression R67) gets the advisory `=== LOCATOR HYGIENE === skipped (...)` line; exit code unchanged.

```
python scripts/lint.py             # full report
python scripts/lint.py --summary   # counts only (close-out friendly)
```

No side effects, and it exits 0 once it has started. The one nonzero exit is a `scripts/_wikilib.py` that is missing, corrupt, or too old to export the link surface: lint parses and resolves links through that shared library (regression R80) and deliberately has no fallback parser, so an unfinished sync says so loudly -- one line naming the remedy, not a traceback, because `maintenance_preflight.py` reports the first stderr line as its blocker -- instead of quietly scanning with a second, diverged copy. (What the guard cannot catch: a copy that still exports the three names with changed *behaviour*. That imports cleanly; keeping the library in step is the sync's job.) Table-cell escaped pipes (`[[foo\|Foo]]`) parse correctly. It matches link targets by *basename*, and strips `#anchors` before resolving — but a dangling anchor **is** caught, by the LOCATOR HYGIENE section below, which delegates to `suggest_anchors.check_anchors_full()` and reports `broken heading anchors N | suspect M` on every run. (This paragraph used to say anchor resolution was "the natural next upgrade"; it shipped 2026-07-28 and gained the suspect tier and block-id validation on 2026-08-09.)

## check_stale.py — staleness detector

`lint.py` finds broken *links*; `check_stale.py` finds *stale content* — the drift that creeps in when a decision is made but its ripple across downstream pages is deferred and forgotten. The mechanical half of an LLM lint pass; the detector behind the **session close-out protocol** in `CLAUDE.md`.

```
python scripts/check_stale.py            # full report
python scripts/check_stale.py --summary  # counts + OVERDUE/DUE lines only (close-out friendly)
python scripts/check_stale.py --days 30  # tighten the central-page age threshold (default 45)
```

Advisory only — never auto-fixes, always exits 0 (a malformed flag exits 2 at argparse). Every line is a *candidate for review*; it can't tell a legitimately-open item from a stale one, so a human (or the session) decides. It reports:

- **A. Open-loops ledger** — open items in `_meta/open-loops.md`, flagging any whose `trigger:` date has passed (OVERDUE). It reads the `[ ]` / `[~]` / `[x]` marker and **nothing else**, so a loop closed only in prose -- a dated CLOSED note under an unflipped `[ ]` or `[~]` box -- keeps reporting open and overdue. Whenever anything is OVERDUE the section prints one reminder saying exactly that (regression R74). The gate is OVERDUE, not *open* -- but a vault carrying a standing overdue loop will see the reminder at every close-out until the marker flips, which is the intent.
- **B. Time-sensitive markers** — `pending ingest`, `NOT yet done`, `TODO`, `needs input`, `==highlight==` (the unverified-claim convention), `placeholder` / `TBD`. Grouped by file with line numbers. Lines struck through (`~~…~~`) or checked (`[x]`) are skipped as resolved.
- **B2. Markers on tracker pages** — tracker pages are *supposed* to carry open items, so their hits report separately as low-signal. **Declare a tracker page by adding `tracker_page: true` to its frontmatter** (preferred — the script stays edit-free and template-syncable; the in-script `TRACKER_PAGES` set still works as a legacy fallback). Pages with `auto_generated: true` are skipped entirely — their markers are engine-emitted, not human drift.
- **B3. Terminal `*(unverifiable:)*` labels** -- the *terminal* counterpart of section B's temporary markers (`_meta/fleet-conventions.md`, marker hygiene). Its reason is a closed vocabulary -- `source-gone` / `paywalled` / `provenance-lost` -- and until regression R57 nothing enforced it: no section-B regex matches the label, by design, so an invented slug left the drift channel silently. B3 counts the valid labels (the population becomes visible) and reports anything else -- an invented slug, or a reason-less `*(unverifiable)*` -- as `INVALID` with its `file:line`. **Printed under `--summary` too**, like OVERDUE and DUE. Same line exemptions as section B (fences, `~~struck~~`, `[x]`), plus `inline code` -- a label in backticks is being quoted, like one in a fence. The synced convention docs and `log.md` are skipped, and a `<placeholder>` reason is never a violation, so quoting the form anywhere costs nothing. **It validates the label's shape, never prose:** a hit counts only if it is italic-wrapped as the convention writes it (which also catches the reason-less `*(unverifiable)*`) or carries a whitespace-free slug-shaped reason (`(unverifiable: could-not-find)`, italics forgotten). An ordinary sentence using the word in brackets -- "disputed (unverifiable without the parish register)" -- is not a label and is never flagged. Header `N valid / M INVALID` is parsed by `maintenance_preflight.py` as the optional keys `terminal_labels_valid` / `terminal_labels_invalid` (prefix match only, so a later suffix on the same line still parses), and each `INVALID:` detail line is carried into its report as a **warning, never a blocker** -- READY stays yes; a header count the detail lines do not cover is itself a warning (regression R109). **Every valid label is then cross-checked against `wiki/log.md`** for the downgrade entry the convention's rule 3 requires (regression R99): a heading `## [YYYY-MM-DD] meta | downgrade | <wiki-relative page path> | <slug>` naming the label's page (forward slashes, `wiki/` prefix and `.md` optional, case-insensitive) and its slug -- matched on page + slug, never on line numbers. A label with no such entry prints `file:line  UNLOGGED: '<slug>' -- no `meta | downgrade` entry in wiki/log.md`, under `--summary` too, and the header becomes `N valid / M INVALID / K UNLOGGED` (appended after INVALID; the R109 prefix match above still parses and the UNLOGGED count is not one of its keys). Hygiene, not validity: the label still counts as valid and the exit code is unchanged. A note that merely quotes the convention (the `[YYYY-MM-DD]` placeholder, a `<...>` field, or a heading inside a fence) never counts as an entry -- the sample-vault-b false positive from R99.
- **C. Central-page age** — pages tagged `central` whose `updated:` is older than `--days`.
- **D. Recurring items due** — any wiki/_meta line carrying a **`Last run: … Next due: ~YYYY-MM`** stamp (the quarterly claim audit, an annual review, …), flagged DUE once that month arrives. The section ends with a **`claim audit:` status line** — `installed [file:line] next ~YYYY-MM`, `NOT INSTALLED` (no stamp's list item names the claim audit — `0 tracked` is *never scheduled*, not *nothing due*; regression R79), or `EXEMPT — <reason>` when a wiki/_meta line records `claim audit: exempt -- <reason>` (a deliberate decision, e.g. a vault whose citation style has no source-citing claims). **This is the reminder mechanism for recurring maintenance**: because check_stale runs at every session close-out, a due item nags every session until it's run and re-stamped — no human memory required. Put the stamps on a recurring-items page and keep the phrasing intact.
- **E. Instance scaffold** -- the required *instance-owned* files a vault must carry: `CLAUDE.md`, `scripts/README.md`, `_meta/llm-wiki.md`, `_meta/obsidian-syntax.md`, `_meta/open-loops.md`, `wiki/index.md`, `wiki/log.md`. None of them is in `sync_from_template.py`'s `SYNC_SET` (instances own their content), so a vault bootstrapped from an older template silently lacks whatever was added later and nothing ever notices -- the gap behind regression R65. Each absent path prints `MISSING SCAFFOLD : <path>` (a distinct token from sync's own `MISSING :`, so a close-out log never conflates the two), under `--summary` too. **Report only** -- the file is bootstrapped by hand from the template and then adapted to the vault's topic; copying it automatically would turn an instance-owned file into a synced one. Conditional layers (`_meta/retrieval-layer.md`, `wiki/data/`, `wiki/analysis/positions-register.md`) are deliberately NOT required: several vaults lack them by design. Header `N required / M missing` is parsed by `maintenance_preflight.py` as the optional keys `scaffold_required` / `scaffold_missing`, and each `MISSING SCAFFOLD :` line is carried into its report as a **warning, never a blocker** (regression R109; an older check_stale without the section parses as before -- no new required key).
- **F. Transcript provenance** -- every *transcript-derived* `wiki/sources/` page must carry `transcript_kind:` from the closed vocabulary in `_meta/fleet-conventions.md` (`auto-captions` / `whisper-local` / `whisper-remote` / `manual-captions` / `official` / `human-verified`; regression R45 -- before it no script read the field, so a transcript page written without it was invisible to every scanner). A page counts as transcript-derived when its **frontmatter** names `raw/watched/` or carries `transcript_source:` / `transcript_kind:`, when it is **tagged** `video` / `podcast` / `lecture` / `talk` / `webinar`, or when its body holds **5 or more distinct `[mm:ss]` timestamps** outside code fences (backtick-wrapped `` `[05:14]` `` counts). A body-only mention of `raw/watched/` is not a trigger (a book page noting how it entered the vault). Findings, one line each, **under `--summary` too**: `MISSING transcript_kind` (with the fix derived from `transcript_source` via the compat map -- `captions (auto)` and bare legacy `captions` -> `auto-captions`, `local-whisper (...)` -> `whisper-local`; unknown provenance -> `auto-captions`), `INVALID transcript_kind` (outside the vocabulary), and `LEGACY LABEL '<label>' -> migrate to <kind>` when a `/watch` label was used as the kind. Legacy labels are **migrated, never grandfathered**; `transcript_source` keeps its verbatim label. Pages outside `wiki/sources/` are not scanned. Header: `N transcript pages / M missing / K invalid / L legacy` (parsed by `maintenance_preflight.py` as an optional key). A transcript page with none of these triggers (a lecture transcript filed as a plain `.txt` with no timestamps or tags) is still invisible -- tag it.

Scans `wiki/` + `_meta/` only (section E stats its fixed path list instead); skips `log.md` (append-only history — always full of marker phrases), the ledger itself, and `raw-clips/` / `scripts/extracted/`. Section B is deliberately a bit noisy (`TBD`/`==verify==` are dual-use) — the design is *surface candidates, let the reviewer filter*, not zero-output.

## audit_claims.py — claim-audit sampler

The fourth mechanical-lint layer: `lint.py` asks *is the graph broken?*, `check_stale.py` asks *is the content stale?*, `audit_claims.py` asks *are the citations faithful?* — and answers only the half a script can answer: **which claims to check**. The judging is reading comprehension and stays with the LLM session.

**Why:** the drift class no other scanner catches is a page asserting something its cited source doesn't quite say — a figure credited to the wrong author, a nuance flattened into a stronger claim. Links resolve, nothing reads stale, but the claim has drifted. Sampling makes that findable on a schedule instead of by luck. (In the originating vault, the first run caught a mis-attribution in 10 samples.)

```
python scripts/audit_claims.py                      # quarterly sample (seed = e.g. 2026-Q2, n=10)
python scripts/audit_claims.py --n 20               # bigger sample
python scripts/audit_claims.py --source some-slug   # audit one source's citations
python scripts/audit_claims.py --include "wiki/concepts/foo.md:42"   # force a claim line into the queue (drills); "wiki/concepts/foo.md:" = every claim line in that file
python scripts/audit_claims.py --root "C:\path\to\vault" --no-history   # audit ANOTHER vault with this copy
python scripts/audit_claims.py --record-run run_record.json   # persist a claim-audit workflow run (no sampling)
python scripts/audit_claims.py --record-verdict 5aa46737a1b27b12=FAITHFUL   # record an in-session verdict by its id=
python scripts/audit_claims.py --include-judged   # ignore the judged-claims ledger (the quarterly deep audit)
```

**`--root PATH`** points the scan at the vault at `PATH` instead of this script's own repo. Without it the paths come from `__file__`, so a **template or worktree copy** run from a vault's cwd audits the *template's* empty scaffold and prints `No citation-bearing claim lines found` -- exit 0, looks clean, exercised nothing (regression R67). That is what made every anchor-stack fix copy the script into the vault before it could be verified. A `PATH` with no `wiki/` exits **2** with a message rather than reporting an empty population. Pair it with `--no-history` unless the run is meant to move the *target* vault's coverage trend. `suggest_anchors.py` takes the same flag.

Always exits 0 (an unusable `--root`, or unusable `--record-run` input, exits 2), stdlib only. **`--record-run JSON`** appends the claim-audit workflow's returned `run_record` (or its whole result) to the `runs` list of `_meta/claim-audit-ledger.json` -- per-vault state, never template-synced -- with a `run` id (`YYYY-MM-DD.k`) and `recorded` date, capped at the last 100 runs, then exits without sampling. It is the escalation telemetry of regression R70: `escalated`, `borderline`, `chart_read`, `lens_disagreement`, `escalation_reasons` and each row's verbatim `escalation` array, kept so several real quarterly audits can be compared before anyone tunes the escalation gate (observe-only; never loosen the gate to cut usage). An unreadable ledger is refused, not overwritten.

**Judged-claims ledger (regression R52).** The `claims` map keeps one row per claim line. Its key is the first 16 hex of sha256(repo-relative path with `/` separators and line text with whitespace runs collapsed); an edit to the line creates a new identity. Each row stores `relpath` and a `sources` map with `verdict`, `last_judged_run`, and `last_judged_period` per cited slug. A top-level verdict summarizes the worst current per-slug verdict for display. Sampling eligibility is determined per slug: a current-quarter FAITHFUL judgment skips that claim-source entry; an absent, UNCONFIRMED, DRIFTED, UNSUPPORTED, or STALE judgment remains eligible. The whole line is skipped only when every cited slug is FAITHFUL. `--include-judged` lifts all skips; forced `--include` entries also bypass them. `--n` counts claim-source entries and NEXT STEPS prints the skipped entry count. Each queue entry prints the line `id=<key>` under its source heading. In-session verdicts use `--record-verdict ID@SLUG=VERDICT`; `ID=VERDICT` is accepted only for an unambiguous single-source line. Workflow rows carry `key` and `slug`; unresolved rows are reported without a judgment. Duplicate judgments for one slug in a run keep the worse verdict. A replay back-fills missing per-slug judgments using its original quarter, and a new run cannot overwrite a strictly newer judgment. Writes prune dead line keys. Legacy flat judgments are attributed to a slug only when the live line cites exactly one source; a flat row on a multi-source line suppresses nothing. The claim-audit workflow passes `--include-judged` by default for the quarterly deep audit; `/ingest` close-out's `--n 5` consults the ledger. Seed plus ledger snapshot reproduces a run. The script also reports locator coverage and a verification queue grouped by source.

Legacy multi-source rows also retain chronology: when a newer judgment migrates one into per-slug facts, `legacy_watermark` preserves the original verdict, run, and period as ordering history only. The watermark blocks older judgments and equal workflow run IDs; replay must be provably newer, while fresh same-day manual judgments retain the existing last-write-wins behavior. It grants no skip coverage and survives partial migration so a stale replay cannot back-fill an unjudged sibling. Missing or invalid workflow verdicts report UNRESOLVED and veto FAITHFUL consolidation for the affected `(key, slug)` in that run, while valid sibling judgments can still be written. Workflow recording keeps exit 0 for unresolved rows; manual CLI target errors still exit 2 before any ledger access.


**`--include` (regression R97).** A spec is `FILE:LINE` (one claim line; `FILE` is a path *suffix on a `/` boundary* -- `foo.md`, `concepts/foo.md` -- forward or back slashes; `s.md` does not match `sources.md`) or `FILE:` (every claim line in that file). It force-includes **every** population entry the spec matches -- one entry per source wikilink on the line, so a line citing two sources (or the same source twice) yields two queue entries, the same one-entry-per-match contract the rest of the queue keeps and the claim-audit workflow counts. Forced entries are prepended, so printed `n=` may exceed `--n`; an entry already in the sample is not added twice (dedupe per entry, by line id + slug + line number, counted as a multiset so a same-source-twice line still yields both entries when the sampler already holds one), and overlapping specs force each entry once. Forced entries bypass the judged-claims ledger skip. A spec with no colon (`positions-register.md`), no path (`:42`) or a non-numeric line (`foo.md:abc`) **exits 2** naming the spec before any sampling or ledger read -- an empty path suffix used to match every page, so such a spec silently forced the first population entry. A well-formed spec that matches nothing prints a `WARNING` on stderr and forces nothing (exit unchanged).

**STRATA telemetry (regression R100).** A `=== STRATA ===` block after LOCATOR COVERAGE, and the same two lines again under NEXT STEPS, count two strata over the whole population and over the served queue, one entry per claim-source entry: `machine-tier: X of N population / Y of M queued` -- the cited `sources/<slug>` page's frontmatter `transcript_kind` is `auto-captions`, `whisper-local` or `whisper-remote` (a legacy label resolves through check_stale's compat map; `manual-captions` / `official` / `human-verified`, an absent kind, or an unmappable one do not count); and `terminal-labeled: ...` -- the citing page, or the cited sources page, carries a VALID `*(unverifiable: <slug>)*` label as check_stale section B3 defines one (INVALID labels, quoted / fenced / struck ones do not count). Telemetry only: the ruling of 2026-09-27 keeps `risk_score` and the draw unchanged until real quarterly outcomes accumulate, so the counts are computed after the sample and read by nothing -- the queue for a given seed is byte-identical with and without them. `--record-run` also stores them on the run entry as an additive `strata` field (population side from the vault at record time, queued side from the run's rows by key + slug); it is ledger-owned like `run` / `recorded` and excluded from the duplicate-record check. The vocabulary and the label scanner are imported from the sibling `check_stale.py` (no bytecode written); a copy run without it -- or beside an older `check_stale.py` lacking a helper the strata use (a mid-sync vault) -- prints `strata unavailable` and samples exactly as before, and `--record-run` there stores `strata: {"note": ...}` with a stdout WARNING -- never zero counts that would read as real data. `population` is the same set in both places: every claim-source entry (after `--source`, before the judged-claims skip), so the queued side is a subset of it. Carry both lines into the quarterly log entry's prose.

**Quarterly workflow:** run → judge each claim FAITHFUL / DRIFTED / UNSUPPORTED / STALE in-session → fix immediately → log it in the exact shape the script's NEXT STEPS block prints → update the `Last run / Next due` stamp on your recurring-items page (section D above watches it). The log-line fields (hits / split / unconfirmed) and the cadence rule are defined in that NEXT STEPS block and nowhere else (regression R63); read it from the script output, not from memory. **Validation loop:** follow the cadence rule the script prints; occasionally run a seeded-error drill — one session plants 2-3 subtle distortions and force-includes them via `--include`, a later session judges blind, and recall <100% means the audit protocol needs sharpening.

## suggest_anchors.py — anchor-backfill assistant (raising locator coverage mechanically)

Companion to `audit_claims.py`, attacking the number it reports: locator coverage. Anchoring hundreds of claims by hand means re-reading every sources page; this script does the reading mechanically. For every **unanchored** source-citing claim (the identical population — it imports `audit_claims.iter_claim_lines`, so coverage moves 1:1), it scores the cited page's sections against the claim line (exact figures dominate — dollars, percentages, and unit-bearing or decimal numbers like `5.28 h` / `HRV 49 ms` / `RHR 47`; rare-term overlap breaks ties) and tiers the result: **AUTO** (a *unique* figure match, above `AUTO_SCORE_MIN`, beating the runner-up by `AUTO_MARGIN` — mechanically applied), **HIGH_REVIEW** (no unique figure, but a *verbatim* section wins decisively — `HIGH_SCORE_MIN` / `HIGH_MARGIN`; anchor pre-filled, so a session skims the batch instead of retyping headings), **REVIEW** (top candidates written to `_meta/anchor-suggestions.json` for a session — or a fleet of cheap subagents, one per sources page — to decide), **NOMATCH** (no section matched; treat as drift candidates for the next claim audit, never force an anchor).

Four scorer rules, each of which was a whole class of bad picks in the field:

- **Verbatim sections win ties.** A section whose body is *mostly the source talking* — a `> [!quote]` block, a `Locators` section, the evidence layer the CLAUDE.md locator rule asks for — is multiplied by `VERBATIM_BONUS`. The largest error class was preferring the wiki-voice synthesis section (`Bearing on positions`, `Key takeaways`) whose phrasing the claim was written *from*, over the quote the claim can actually be verified against. Dominance is the test, not presence — a synthesis section that quotes a line or two is still wiki voice.
- **Generic headings are not locators.** `Links`, `Citations`, `Status`, `See also`, `Wiki edits prompted by this source`, or a heading that just restates the page title (`Source: ...`) are excluded from scoring entirely (still valid for `--check`, since older anchors may point at them). The link-inventory half of that test *is* `audit_claims.SKIP_HEADINGS`, imported rather than re-typed, so the two scripts cannot drift apart.
- **One line, several citations, one winner.** When scoring a line for source X, every wikilink span that is not `sources/X` is masked out first, display text included — otherwise a line citing three sources scores its full text against each and all three anchors converge on the same section.
- **The page is parsed the way Obsidian reads it.** `##` lines inside fenced code blocks are not headings (a ```` ```markdown ```` block quoting a template would otherwise donate sections that don't exist — and `--check`, reading the same structure, would validate an anchor Obsidian can't resolve). H1 counts as a real heading for `--check`, but only wins anchors on pages with no deeper headings; elsewhere the lone H1 is the restated page title.

Both mechanical tiers are tuned on a **backtest against hand-verified anchors** (341 claims, sample-vault-c vault, 2026-07-29): **AUTO 12/12 and HIGH_REVIEW 32/32 correct**, covering 13% of the population mechanically. Precision comes from the margin rule, not the score floor — the residual errors are confident picks of a plausible-but-wrong section, so score thresholds alone never got past ~0.73. Re-tune by moving the four module constants and re-running the backtest; nothing else in the tiering should have to move.

```
python scripts/suggest_anchors.py               # scan -> _meta/anchor-suggestions.json + per-source table
python scripts/suggest_anchors.py --summary     # tier counts only
python scripts/suggest_anchors.py --apply-auto  # apply the AUTO tier, then validate
python scripts/suggest_anchors.py --apply-all   # apply AUTO + HIGH_REVIEW, then validate
python scripts/suggest_anchors.py --apply F.json  # apply reviewed decisions (entries with non-empty "anchor")
python scripts/suggest_anchors.py --check       # validate ALL existing anchors resolve (exit 1 on breaks)
python scripts/suggest_anchors.py --root "C:\path\to\vault" --summary   # scan ANOTHER vault with this copy
```

`--root PATH` behaves as it does for `audit_claims.py` above (regression R67) -- with one warning: the apply modes and every scan **write** under `--root` (`_meta/anchor-suggestions.json`, the applied anchors themselves), so a worktree copy can mutate a live vault. Scan before you apply.

The apply modes also write **`_meta/anchor-auto-applied-latest.json`** -- the pages and lines that actually took an anchor (`{rel, lineno, slug, anchor, tier}`, SKIPs excluded, and an entry is recorded only after its page's write returns), rewritten unconditionally so it is never stale, and stamped with a full `generated` timestamp so a later reconciliation can tell this run's record from a leftover without trusting a Dropbox-rewritable mtime. `_meta/anchor-suggestions.json` cannot serve that purpose: the next scan lists only *unanchored* claims, so it drops every entry that just landed, and the `anchor-backfill` workflow re-scans one command later. The maintenance pass reconciles the run's disk changes against this record (regression R94). `--apply FILE` deliberately does not write it -- the decisions pass has its own JSON, and writing here would clobber the Scan step's list.

`--check` exists because `lint.py` deliberately strips `#anchors` before resolving links — nothing else verifies an anchor names a real heading.

Matching runs in **two tiers**, and the distinction is load-bearing:

- **strict** (`strict_heading()`) strips asterisk emphasis, collapses whitespace, casefolds. Nothing else. This is Obsidian's actual rule as far as it has been observed.
- **lenient** (`norm_heading()`) additionally folds *all* punctuation to spaces.

An anchor matching strictly is clean. An anchor matching only leniently is reported **SUSPECT** — the checker vouches for it but Obsidian may not. That gap is not theoretical: on 2026-08-08 an anchor spelling a heading's em-dash as `--` passed `--check` and still landed at top-of-page, because both spellings survive `norm_heading`. Suspects are counted and printed separately by `lint.py` and are **never** added to the broken count, since leniency is a superset and some of what it forgives does resolve (asterisk emphasis, confirmed 2026-08-09 by clicking one in Obsidian). Block-id (`#^id`) citations are validated against the target page's actual block ids.

Rule of thumb the two tiers encode: **an omitted formatting marker is safe; a substituted character is not.**

Click-tested 2026-08-08/10, so the tiers are calibrated to observation rather than to a model of Obsidian. **Resolve:** emphasis markers dropped from the anchor; a leading list marker's period dropped; straight apostrophes and double quotes carried verbatim. **Does not resolve:** an em-dash respelled `--`. Consequence for fixing a broken locator: **an ASCII heading can always be anchored verbatim** -- quotes and apostrophes are not link delimiters -- and a `^block-id` is needed only when the heading holds a character the write-guard cannot write. Put that id at the **end of the cited paragraph**, not on the heading line (confirmed by click; also 66 of 67 existing ids across the fleet).

Apply modes now record the post-apply coverage datapoint to `_meta/locator-coverage.json` automatically (same writer as `audit_claims.py`), so no manual re-run is needed to keep the trend honest.

Applies are **line-surgical**: line counts never change, table pipe-escapes survive, and reads/writes are byte-transparent (`newline=""`), so anchoring one line does not rewrite an LF-authored page as CRLF — a whole-file diff in git and a whole-file re-sync for the Dropbox instances. A line whose **recorded text no longer matches is refused, not guessed at**: a decisions file written by one run and applied by a later one can have drifted, and if the shifted-to line cites the same source the anchor lands on the *wrong claim* — an error `--check` cannot see, because only the pairing is wrong. Every apply mode writes `_meta/anchor-suggestions.json` *before* editing, so the record of what it chose survives the run that made the edits.

A winning heading containing link-breaking characters (`` [ ] | # ^ ` \ ``) is never written as an anchor; instead the anchor **falls back** to the nearest linkable ancestor heading — a coarser locator, but a real one, marked `"fallback": true` in the JSON so the choice stays auditable. **Asterisk emphasis is not link-breaking**: `anchor_text()` strips it before writing, and the stripped form resolves, so a heading carrying `*emphasis*` (the shared source-page shape) is anchorable rather than permanently disqualified. Because a fallback links the *parent* of the section that actually matched, fallbacks are **REVIEW-only** — never AUTO or HIGH_REVIEW — and a human accepts one via `--apply` or does better. The scan also separates the **structural ceiling** out of NOMATCH: claims citing a page with no anchorable section at all (no headings, or only bookkeeping ones) can never be anchored by any amount of judgment, and the fix is to give that sources page substantive sections, not to re-read the claim. First deployment (sample-vault-f wiki, 2026-07-28): 359 unanchored → 64 AUTO applied + 8 pre-existing broken anchors caught (one cited the wrong author), coverage 17% → 32% in one pass.

## screen_capture.ps1 -- ebook page capture (Windows-only)

Captures a book you own from a desktop reader (Example Reader by default) as a folder of `page_NNN.png` frames: screenshot the reader window -> send a page-turn key -> repeat. For books that only exist behind a reader app -- when the source is a DRM-free epub, use `extract_chapter.py` instead. The frames land in `raw/` and are ingested by reading the images directly; the reader's footer (`N CHAPTER -- x/y`, e.g. `3 THE GOOD NEWS -- 4/5`) serves as the locator in place of print page numbers.

```
powershell -ExecutionPolicy Bypass -File scripts\screen_capture.ps1 -WindowTitle "Reader window title" -Pages 17 -OutDir raw\my-book\chapter-1
```

`-Pages` is required -- open the chapter and read its screen count off the first page's footer ("1 / 17"). Capture **chapter-at-a-time** into one folder per chapter; a misfire then costs one chapter, not a book. `-WindowTitle` (default `'Example Reader'`), `-TurnKey` (default `{RIGHT}`), and `-DelaySec` (default 1.0, fractions fine) adapt it to other readers.

The method, proven on two full books (regression R30):

1. **Grab TOC + copyright pages first** (manually or as a small run) -- that's the edition info the `sources/` citation needs.
2. **Verify one mid-book frame** shows complete right-margin text before trusting a long run.
3. **If a run overshoots** past the chapter end, trim by the footer text, not just content-hash dedupe -- the reader keeps "turning" past the last page and can capture its library view.

**Recipe: archive.org BookReader in Chrome (browser readers that lazy-load pages)** -- validated 2026-09-13 in sample-vault-c on an archive.org borrow (regression R59): a run at the default poll cap aborted ("frame 20 did not stabilize after 10 polls", 19 of 58 frames written, `completed: false`); all six post-abort runs completed with 0 turn retries. BookReader loads each page image progressively, so the default settle window (10 polls at 100 ms, a bit over 1 s) is too short. Pass `-DelaySec 2 -MaxStabilizationPolls 60`: raising the poll cap is free on pages that settle (polling stops at the first stable pair; only a never-settling frame takes ~6 s instead of ~1 s to abort), while `-DelaySec 2` costs +1 s per page over the 1.0 default. The default stays 10 on purpose -- the long window is a per-reader choice, not a new default. Working invocation (from the vault root; `-WindowTitle` is the prefix of YOUR book's Chrome tab title):

```
powershell -ExecutionPolicy Bypass -File scripts/screen_capture.ps1 -WindowTitle "Better training for distance runners" -TurnKey "{RIGHT}" -Pages N -DelaySec 2 -MaxStabilizationPolls 60 -OutDir raw/<book>/<block>
```

- **Maximize the Chrome window.** The "Reader window extends off-screen" throw that the 2026-09-13 run hit on a maximized window (worked around with `SW_RESTORE` + `SetWindowPos`) is superseded by the DWM-rect fix (regression R47) -- no workaround needed.
- **A follow-on run's first frame repeats the previous run's last page.** After a completed run it is mechanical: runs end without a trailing page turn (seen at p. 238). After a "did not stabilize" abort the turn for the failed frame HAS been sent, so where the reader stands is not guaranteed -- resume by navigating back to the last captured page (e.g. by URL), and the new first frame repeats it (seen at p. 200). Expected, not a splice: confirm the two frames show the same running-head page number before dropping one; if they differ, nothing is duplicated.
- **Locators are the printed page numbers in the running head, not archive.org's URL page index** -- the URL index is offset from print (printed 182 = `n209` in that book), so never cite the URL number. BookReader frames are images of the printed book, so the running-head number is a true print page (unlike ebook reader's reflowed `x/y` screen counter, which `_meta/book-scanning.md` forbids turning into a page number); cite it in the fleet `p.NNN` form.

Safety properties (each one learned the hard way -- don't remove them):

- **Captures only the reader window's visible frame** (DWM extended frame bounds, *not* `GetWindowRect` -- that rect includes Windows' invisible ~8px resize borders, so every frame carried strips of whatever sat behind the window: a privacy leak, plus a stabilization deadlock whenever anything animated sat under a border strip, regression R48). Never the full screen, and **fails closed on focus AND geometry**: aborts if the reader window can't be verified as foreground by title, loses focus mid-run, or moves/resizes mid-run (both re-checked before every frame) -- so it can never screenshot a terminal or mail client and call it a book. A failed rect query aborts too; there is no fallback to the raw window rect. To abort a run deliberately, click any other window.
- **A maximized reader is the supported case** (regression R47). The off-screen guard compares that visible frame against `SM_*VIRTUALSCREEN` in physical pixels; it used to compare the border-inclusive rect, which overhangs the monitor on every side, so it rejected *every* maximized window -- the layout `_meta/book-scanning.md` prescribes. A **minimized** reader passes the title gate but its geometry is the taskbar button, so the script asks `IsIconic` before reading any rect and aborts with `the reader window is minimized -- restore it (maximized is the supported layout) -- nothing was captured` (regression R102; it was the 199x34 "implausibly small" abort, not a phantom thumbnail window); it never restores the window for you -- fail closed, and the `<200x200` throw stays as the backstop. Consequence for old captures: post-fix frames are ~18px smaller per axis, so a re-capture of a chapter already in `raw/` will not be pixel-identical to the frames beside it; `run-manifest.json` records `rect_source: dwm_extended_frame_bounds` so a folder's origin stays checkable.
- **Scope of the foreign-pixel fix, measured rather than assumed:** exposure is eliminated along the straight edges, and *entirely* for a maximized reader -- a maximized window has square corners and its visible frame equals the work area. A **restored** window's visible frame is still the bounding box of a *rounded-corner* frame, so four ~9px corner arcs can composite whatever is behind (a pixel probe over the edge strips measured 144/9450 residual non-page pixels there: the window's own frame line plus those arcs). This is why the restored-window path recorded in regression R59 (`SW_RESTORE` + `SetWindowPos` for archive.org BookReader in Chrome) is now the worse option -- maximize the reader instead.
- **Verifies page advancement AND frame stability**: a frame byte-identical to the previous one means the page turn didn't land (the footer counter changes every real page); the turn is retried (`-MaxTurnRetries`, default 2), then the run aborts incomplete rather than certifying duplicate frames as pages. Once a change appears, the frame must hold still for two consecutive captures (`-MaxStabilizationPolls`, default 10 at 100 ms) so a mid-animation or half-rendered page can't be committed. DPI awareness is verified at startup and fatal if absent (cropped-frame protection). Side effect: an overshot `-Pages` now stops at the last real page instead of capturing the library view.
- **Refuses a non-empty `-OutDir`** -- numbering restarts at `page_001` every run, so reusing a folder would splice two runs into one plausible-looking page sequence.
- **Writes `run-manifest.json`** (frames written, turn retries, completed flag, abort reason, rect source) -- ingest should check `completed: true` before trusting a folder.
- Declares itself DPI-aware -- without that, captures on a scaled display silently lose the right/bottom ~20%. DPI awareness is established *before* any rect is read, because DWM reports physical pixels and a virtualized process's other geometry calls do not.

Geometry regression test (Windows, interactive desktop -- it shows its own throwaway window for about a second; launches nothing else and captures no pixels):

```
powershell -ExecutionPolicy Bypass -File scripts\tests\test_screen_geometry.ps1
```

## verify_capture.py -- footer-OCR geometry scanner for capture runs

Replaces the manual first/middle/last-frame read that every whole-book capture ingest starts with (regression R49). For each `page_NNN.png` it crops the reader's footer strip (bottom ~4.5% of the frame height, middle half of the width), OCRs it with Tesseract, and parses `SECTION -- x / y` (en/em dashes folded to `--`; `x/y` unspaced is fine; a bare `x / y` with no name -- promo screens -- parses as an unnamed section).

```
python scripts/verify_capture.py raw/book/FrontMatter raw/book/Part1 raw/book/Part2 --out-dir C:\tmp\book-map
```

- **`--out-dir` is required** and may not be (or be inside) a run directory, nor anywhere beneath a vault's `raw/` tree -- the path is canonicalized first (`..`, junctions, symlinks and alternate spellings resolve before the test), so derived output never lands beside the frames or anywhere in `raw/` (regression R50 ruling; raw/-wide refusal ruled 2026-09-26). It receives `screen-map.md` (run | page | footer | section table + flags + section transitions) and `screen-map.json` (same, plus each frame's sha256 and raw OCR).
- **Pass run directories in capture order** (each `run-manifest.json` carries `started`): they are checked as ONE stream, so a screen skipped or captured twice at the boundary between two runs is caught.
- **The `x / y` counter is the continuity spine**, not the name beside it: ebook reader counts screens per TOC chapter while the name is the nearest heading and can change mid-chapter, so a name change is listed as a transition, never flagged.
- **Flags** (exit 1): `GAP` (a counter step other than +1, a chapter left before `y/y`, a chapter entered past `1/y`, or the stream ending mid-chapter -- `completed: true` only proves `frames_written == -Pages`), `Y-MISMATCH` (chapter total changed mid-chapter: reflow or misread), `DUPLICATE` (byte-identical frame, or the same footer twice in a row -- two captures of one screen are rarely byte-identical; for `1/1` screens only when the names match exactly after OCR folding, since consecutive one-screen chapters like `PART G` / `PART H` or two unnamed plates are distinct), `FOOTERLESS` (no counter: the ebook reader library grid, reader chrome), `UNREADABLE` (a counter is visible but did not parse -- look at the frame), `BADIMAGE` (the frame could not be read or OCR'd, e.g. half-written), `MANIFEST` (missing/unreadable/non-object manifest, `frames_written` vs files on disk, numbering holes, 0-frame failed run, `completed: false` with its abort reason, `completed: true` with `frames_written != pages_requested`). A `NOTE` (not a flag) says when an incomplete run's last footer closes its chapter and only footer-less frames follow -- likely the true book end, nothing to recapture -- or when a run has no footer counters at all.
- **Blind spot:** a whole chapter skipped between two finished chapters (`3/3` then `1/4`) is invisible to the counter; compare the section transitions against the book's TOC.
- Exit 0 clean, 1 flags, 2 usage error or missing dependency.
- **ebook reader-footer readers only.** A reader with no footer counter (archive.org BookReader) reports every frame `FOOTERLESS`.
- Speed: ~0.4 s/frame (139 frames of one book capture in 57 s).

Measured on one book capture in sample-vault-c (5 runs, 139 frames): it reported exactly the three situations the 2026-08-12 manual pass had to find -- the Part III divider captured twice across runs, the skipped promo 2/2 between TheStrategy and AppendicesandCloseout, and the incomplete final run whose footer-less page_028 follows `ALSO AVAILABLE FROM VELOPRESS -- 1/1` (book end).

**Dependencies (lazy, optional):** Pillow, pytesseract, and the Tesseract binary (`pip install pillow pytesseract`; Windows binary: the UB-Mannheim build, or point `--tesseract-cmd` at it). They are imported only when the script runs, so `--help` and `help.py` work without them; a missing one prints a one-line remedy and exits 2.

```

- **Where references live:** `<vault>/.transcripts/` by default for both scripts (`--out` / `--refs` override). Never `raw/` -- these are derived files. A dot-folder because Obsidian hides it and `lint.py` / `check_stale.py` / `suggest_links.py` walk `_meta/` recursively and would read the adjudication packets as wiki pages. Downloaded audio is deleted once its `whisper.json` lands.
- **A starved run is loud (regression R75).** When no page has any reference, `verify_quotes.py` prints `NO REFERENCES LOADED -- run gather_transcripts.py first; MISS counts are meaningless` as its FIRST line and exits 2 -- before this, an unfed run reported 104/104 MISS on the sample-vault-f vault. A page with no reference gets `NO-REFS` spans, a `WARNING` line, and exit 1.
- **Fallback:** a page whose video has nothing gathered uses the transcript embedded in its `report.md` (`## Transcript` section) as the `contemp` reference, with a `NOTE ... FALLBACK` line. On the sample-vault-f vault the fallback alone reproduces the gathered tally exactly (both 62 VERIFIED-CAPTIONS-ONLY / 9 NEAR-MISS / 34 MISS, 2026-09-26) because every video there is auto-captions only; run `gather_transcripts.py` for the manual-caption and Whisper witnesses.
- **Optional dependencies, each loud when absent:** `yt-dlp` on PATH (caption/audio download; absent -> WARNING, contemp only); the `/watch` skill at `~/.claude/skills/watch/scripts` (VTT parsing and `whisper_local.py`; absent -> WARNING, VTT tracks skipped, contemp + existing `whisper.json` still used).
- **Scope:** quoted spans only. A clean run means "the words inside quotation marks are real", not "the page's figures are right".
- Exit (`verify_quotes.py`): 0 every page had a reference; 1 some page had none or was SKIPPED; 2 no references at all or a bad `--page`. `--root VAULT` on both scripts points them at another vault (read-only there when `--out`/`--refs` points elsewhere).

## suggest_links.py — link-graph curation aid ("which pages should link but don't?")

The third layer of the mechanical-lint stack: `lint.py` asks *is the graph broken?*, `check_stale.py` asks *is the content stale?*, `suggest_links.py` asks *is the graph under-connected?* Adapted from graphify's algorithmic "surprising connections" report (github.com/safishamsi/graphify). Builds the wikilink graph, clusters it with Louvain community detection (deterministic, seed=42), and reports:

- **Communities** — topic clusters, labeled by highest-degree member; sanity-check against your real topic areas.
- **Weakly connected** — pages with exactly one inbound link (one deletion from orphanhood; `lint.py` only catches zero-inbound).
- **Candidate missing links** — same-community page pairs with no direct link, ranked by Adamic-Adar (hub neighbors discounted so index-style pages don't drown the signal).
- **Missing back-references** — one-way pairs where A links B ≥2× but B never links back, scoped to content pages; capped at ≤2 rows per linker so aggregator pages can't flood it.
- **Single-edge bridges** — cluster pairs joined by exactly one link: fragile seam or interesting connection.

```
python scripts/suggest_links.py
```

No arguments, no side effects, always exits 0. **Advisory only** — "no link" is sometimes the right answer. Requires `networkx >= 3.0` (`pip install networkx`) — the one non-stdlib script here. Occasional curation tool (quarterly / after big ingest batches), **not** part of session close-out; track last-run/next-due with a `Last run: … Next due: ~YYYY-MM` stamp so section D of `check_stale.py` nags when due.

## llm_suggest_links.py -- local-LLM unlinked-mention finder

Complements `suggest_links.py`: that tool infers *which pages should be related* from graph structure; this one finds *pages already mentioned in prose but not wikilinked*, using a **local Ollama model** to tell real references from coincidental word matches -- zero cloud tokens, built for quota-exhausted sessions.

The task is shaped so a small (7-14B) model only ever answers one narrow question: (1) a deterministic prefilter finds whole-word title/alias mentions in the page's prose (wikilink spans and code masked out; alias-aware "already linked" check); (2) the model sees the candidates *with each page's `description:`* -- the field that resolves word-sense collisions -- and picks the genuinely referenced ones (forced JSON, temperature 0); (3) validation only accepts picks from the candidate list, so the model structurally cannot invent a page. Honest limit: layers 1/3 prevent *broken* links, the description-armed judgment prevents most *wrong* links, and human approval is the final word-sense check.

```
python scripts/llm_suggest_links.py                  # dry-run: print suggestions
python scripts/llm_suggest_links.py --page wiki/entities/foo.md
python scripts/llm_suggest_links.py --limit 5        # stop after 5 pages with candidates
python scripts/llm_suggest_links.py --write          # append NEW suggestions to _meta/suggestions/links.md
python scripts/llm_suggest_links.py --include-seen   # also re-report previously written pairs
```

### Running it on a vault (the no-thinking version)

For each wiki vault (NOT this template). Open a terminal **in that vault's folder** -- the one containing `wiki/` and `scripts/`.

1. **First time only, or after the tooling changes** -- install/update the script. Run this line **twice** (pass 1 updates the sync tool itself; pass 2 pulls the actual scripts):
   ```
   python scripts/sync_from_template.py --apply
   ```
   Done when it says `Done -- 0 file(s) updated`. You do NOT redo this every time -- only when a new/updated script needs to reach the vault.
2. **Make sure Ollama is running** (the local AI). If it isn't, the script just prints a notice and does nothing -- no harm.
3. **Scan the vault:**
   ```
   python scripts/llm_suggest_links.py --write
   ```
4. **Review in Obsidian:** open `_meta/suggestions/links.md`. Each row is a proposed link. **Make the edit on the page = accept. Delete the row = reject forever** (re-runs stay quiet about deleted rows). Obsidian is only needed for this step -- steps 1-3 are just a terminal.

   > **Check every proposed link in context.** A word may refer to a different concept or entity. For example, "Mercury" can mean a planet, an element, or a named project. A mention alone is not enough to accept the link.

Day-to-day, scan and review suggestions before accepting any edits.

**Never edits wiki pages.** `--write` appends checkbox rows to `_meta/suggestions/links.md` and records every written (page, target) pair in `_meta/suggestions/seen.json` -- so deleting a row *rejects* it permanently and re-runs stay quiet about it (`--include-seen` overrides). Approve a row by making the edit on the page. Suggested targets are written as backticked inline code deliberately -- they are *proposed* links, and inline code keeps them out of the Obsidian graph and lint's inbound counts until applied (the "never backtick wikilinks" rule protects *intended* links; these aren't yet). Model responses are cached in `_meta/llm-link-cache.json` (keyed on model + prose + candidates), so warm re-runs cost seconds; delete the file to force a full re-judge.

Skips pages with `auto_generated: true` or `no_autolink: true` frontmatter, plus `log.md` (append-only by convention); code blocks and existing wikilink text never match. Model/endpoint configurable via optional `_meta/local-llm.json` (`{"model": "qwen2.5-coder:14b", "endpoint": "http://localhost:11434"}`) -- config beats editing this synced script. Default is a local [Ollama](https://ollama.com) server; exits 0 with a notice when Ollama is unreachable, so instances on machines without it lose nothing. Advisory, occasional-use (after ingest batches), not part of session close-out.

**Cloud opt-in:** a model whose name starts with `claude-` (e.g. `{"model": "claude-opus-4-8"}` in `_meta/local-llm.json`) is instead routed to the Anthropic Messages API via a raw-HTTP path -- forced-JSON via `output_config.format`, needs `ANTHROPIC_API_KEY`, spends cloud tokens. This defeats the zero-token point, so it's mainly for benchmarking cloud vs local (see `tests/`); the default stays local. Exits 0 with a notice if the key is unset.

## _wikilib.py -- shared parsing helpers

Single source of truth for the wikilink regex (`LINK_RE`), link resolution against the vault inventory, frontmatter boundary/value/flag parsing, alias lookup, and code stripping. Not a script -- imported by sibling scanners (`import _wikilib` resolves because they run as `python scripts/x.py`). New scripts import from here; older scanners still carry inline copies and migrate when next touched. Synced from the template (it's in SYNC_SET alongside its importers).

The link surface, used by `lint.py` (regression R80):

| | |
|---|---|
| `iter_wikilinks(text, strip=True)` | yields `(target, anchor, display, span)` per `[[link]]`; strips fenced **and** inline code spans (single and double backtick) by default. Spans then index the *stripped* text -- a caller that rewrites a file in place passes `strip=False` and handles code spans itself. **Known gap:** a same-note `[[#Heading]]` link has no target and is not yielded; a caller needing those finds them itself. |
| `build_index(paths, texts)` | lowercased page-name/alias -> paths, the vault inventory `resolve` needs. More than one path = a basename collision (regression R76), returned whole. Alias keys are indexed to find the page a link was *meant* for -- they are not Obsidian link targets (regression R151). |
| `canonical_paths(target, candidates)` / `link_kind(target, candidates, vault_basenames=None)` / `vault_md_basenames(root)` | classify a `"resolved"` hit: the candidates whose own basename is the target (the inventory pages Obsidian opens -- the ones to credit), and `"canonical"` vs `"alias-only"`. A caller asking "will Obsidian open this?" must use `link_kind`, not `resolve()`'s status alone (regression R151), and pass `vault_basenames=vault_md_basenames(root)` (every `.md` basename outside dot-directories): without it the result ignores `.md` files that are not in the index (`raw/`, `templates/`), so a name that is such a file AND an alias reads `"alias-only"` although Obsidian opens the file. lint passes it. |
| `lint_inventory(root=".")` / `lint_link_kind(target, from_path, inv)` | lint.py's own inventory (file list, texts, asset names, index, vault basenames) and its verdict on one link: `ghost` / `skip` / `attachment` / `broken` / `canonical` / `alias-only` / `cross-vault`. lint.py calls exactly these, so the answer is lint's by definition -- including dotted-name mangling (a dotted name `splitext` reads as an extension is `broken`) and '/' or ':' name mangling (`/` or `:` split by `basename`, platform-dependent). |
| `resolve(target, from_path, index, root=".")` | `("resolved", paths)` / `("cross-vault", [])` / `("broken", [])`. Trims an explicit `.md` before the basename lookup, and the basename lookup wins over the path -- so a wrong-depth `../` link naming a real page still resolves (matches Obsidian, so not a bug to fix here; `lint.py`'s Relative-depth section checks those on disk, regression R76). Non-`.md` embeds (`![[chart.png]]`) are the caller's asset question. |

> **A one-off link scan that did not go through `_wikilib` is not a finding.** This binds session-written sweeps, new scanners, and skill steps -- not the shipped scanners that still carry inline copies under the migrate-when-next-touched policy above. Two ad-hoc reimplementations written in one afternoon (2026-09-17) produced two *different* wrong answers: one read backticked `[[examples]]` quoted in an append-only `log.md` as live links and filed two false findings as vault work; the other stripped code spans correctly but resolved every target as `path + ".md"`, so it called `[[../CLAUDE.md]]` broken. The weaker interim rule -- "a scan that has not stripped code spans is not a finding" -- would have caught only the first. The rule set is open-ended; importing it is the only way to get all of it.

> **ANY script in `scripts/` that imports a sibling from this folder -- template-synced or instance-local (a vault's own monitor, recipe helper, ...) -- sets `sys.dont_write_bytecode = True` ABOVE the import.** Vaults are cloud-synced (Dropbox) folders, so importing a sibling drops `scripts/__pycache__/*.pyc` into the vault on every run and re-syncs derived files to every device (regression R83/R119). Placed *below* the import the flag is a no-op. `lint.py`, `suggest_anchors.py` and `llm_suggest_links.py` carry it today, and `tests/test_no_bytecode.py` exercises exactly those three -- a new importer is not covered by it. `sync_from_template.py --apply` sweeps leftover residue, but only the guard stops an instance-local importer from recreating it between syncs.

```
python scripts/fix_wikilinks.py            # dry-run: show what would change
python scripts/fix_wikilinks.py --apply    # make the edits
python scripts/fix_wikilinks.py --root PATH # target another vault explicitly
```

Covers `wiki/`, `_meta/`, `CLAUDE.md`. `--apply` holds the per-vault run lock shared with `--alias-only` (ADR-0007; refuses with exit 2 while another fix_wikilinks writer holds it, or where the lock is unreachable -- use `python -B`, not the Store `python3`). Dry-run by default; keep it around — clipper output and pasted notes reintroduce the pattern.

### --alias-only -- rewrite grey alias links to `[[slug|Display]]` (regression R151)

Remedy for lint's ALIAS-ONLY section. The modes are mutually explicit: `--alias-only` never runs the backtick pass, the default mode never rewrites alias links (it matches the pre-alias-only script's stdout, exit codes and bytes, pinned by `test_fix_wikilinks_invariants.py` I2 in shared and standalone-fallback mode, with no divergence -- including a BOM-prefixed `append_only` page, which default mode, like the pre-alias-only script and the preflight gate, still does not see as flagged; BOM-aware flag reads for default mode and `maintenance_preflight` are a separate follow-up), and `--manifest` / `--batch-size` / `--max-files` / `--verify` / `--restore` without `--alias-only` are usage errors (exit 2, nothing written; `--max-files` also needs `--apply` and N >= 1). Flags are spelled in full (`allow_abbrev=False`); only the prefixes the pre-alias-only parser accepted (`--a`..`--appl`, `--r`..`--roo`, `--h`..`--hel`) stay as hidden aliases, so old command lines such as `--r PATH` / `--a` still mean `--root` / `--apply` (review h2-I2-argparse-abbrev-divergence). No guessing: a destination is automated only when exact, case-insensitive name equality proves it unique -- there is no similarity or closest-name matching anywhere. A `#heading` / `#^block` fragment is split off before the alias lookup and re-attached unchanged to the canonical slug. Slug filenames stay; a link whose target is a frontmatter alias of **exactly one** page is rewritten to point at that page's slug with the alias kept as display text: `[[Soil Acidity]]` -> `[[acidity-notes|Soil Acidity]]` (an existing `|display` and `#anchor` are kept; the separator of the rewritten link is written `\|` on a line inside a real GFM table block -- ALWAYS, even when the original link had a bare `|`, since a bare pipe inside a table splits the cell in Obsidian and keeping it would keep the link broken (~22 such links in one large vault); only the link being rewritten changes, other links on the row are untouched. A real GFM table block is a header row immediately followed by a delimiter row (`---`, `:--`, `--:` cells, same cell count), then its rows until a blank line, a row dedented out of the table's list item, or the start of another block (list item, heading, fence, thematic break, a CommonMark HTML block start -- types 1-6, or a line that is one whole tag, never an inline tag or `<https://...>` autolink inside a row -- blockquote-depth change); leading pipes are optional and a table inside a `>` callout counts the same. A pipe-less line after the rows (or one whose only pipes are escaped) is a lazy continuation ROW under the GFM rule (spec example 202), so it is table context and gets `\|` (review t2-R2-T2, reversing t1-LAZY-1): the escaped form is the safe choice under either renderer reading -- if the renderer follows GFM a bare `|` there splits a cell and breaks the link, and if it ends the table `[[slug\|Display]]` still resolves. Cells are counted the way GFM and Obsidian split a row: on every unescaped `|` (a backslash escapes the next character, so `\\|` is an escaped backslash then a separator), inside inline code spans and `[[...]]` too -- such a `|` never MAKES table context on its own, but inside a header row it does split cells, so a header whose cell count then differs from the delimiter row is no table (review t1-R1-T2/T3). A table opening a list item (`- | a |`) needs its delimiter and body rows at the item's content column; any other table's rows are measured from the header's own indent, floored at the content column of the innermost list item still open at the header (a table in a list continuation, e.g. 4 spaces under a nested bullet or a `1.  item`, stays a table, and a row dedented below that column closes the item and so ends the table -- such a line gets a plain `|`; review t2-R2-T1); a delimiter or body row 4+ columns past that column is indented code, not a row (review arb-M2). A line that merely looks like a row never makes table context; outside a table an existing separator is kept as written and a new one is a plain `|`; embeds keep their `!`). Every rewrite is self-checked -- it must parse back to the same page as a canonical link -- before it enters the plan. Only uniquely determined transformations are automated; everything else goes to the **review queue** and is never written:

- `alias-ambiguous` -- the alias is carried by more than one page;
- `stub-collision` -- a 0-byte stub file shares the name with another page's alias (regression R150);
- `name-collision` -- the name is BOTH some real file's name anywhere in the vault (`raw/` and `templates/` included; Obsidian opens that file) AND another page's alias (the page the author may have meant). Competing semantics, so a human decides; case variants count (`[[MULCH]]` vs `Mulch.md`, two files `Case.md` / `case.md` plus an alias `CASE`);
- `alias-unique-held` -- unique, but an empty anchor/display, a slug that cannot be spelled as a link target, or a failed self-check; or one of the never-rewritten forms below, named in the item's `reason`:
  - `in-frontmatter` / `in-code` -- a link lint counts but this fixer masks (frontmatter, a `~~~` fence, a code span crossing a line, indented code, a `<pre>`-type block, a backtick fence lint pairs differently);
  - `path-form` -- `[[concepts/Alias One]]`, `[[../nowhere/Holder Name]]`: a path whose last segment is an alias (an ambiguous one is filed as `alias-ambiguous` with the same reason);
  - `out-of-scope file` -- an alias link in `scripts/*.md`, which lint scans but this fixer never writes;
  - `lint-canonical` -- lint.py already resolves the link to a page (its `lint_kind` is `canonical`), so a rewrite would redirect a link lint counts as healthy. Only links lint files as ALIAS-ONLY, or as BROKEN through dotted / `/` / `:` name mangling, are ever rewritten; every dry run and `--verify` prints `SAFE PARITY: SAFE_REWRITES N = lint-alias-only a + lint-broken b` and exits 5 (no manifest) if any safe rewrite falls outside those two, and `--apply` refuses such a manifest (arb-I9-1);
  - `lint-hidden` -- the reverse of `in-code`: a link live to Obsidian and this fixer that lint's code-strip masks (e.g. lint pairs a mid-line ` ``` ` as a fence). A link is rewritten only when lint also sees it, so this is also the backstop for any block rule the mask gets wrong. The item carries `"lint_hidden": true` (also on ambiguous / stub-collision / held items of the same shape, whatever their `reason`).

A slug containing a backtick is held as `unsafe-slug` (the backtick would pair with a later one and turn the rewritten link into code). `[[wrongdir/foo]]` where some `foo.md` exists is canonical -- lint resolves the basename to it -- and never an alias candidate. The same basename rule wins over an alias spelled with `/` or `:`: an alias `notes/foo` or `C:foo` (lint's `os.path.basename` splits a leading drive on Windows) while `foo.md` exists is a `name-collision` review item, never rewritten (review h1-I6-1). An escaped `\![[Alias]]` is a literal `!` plus an ordinary link, so it keeps its display.

Never touched (masked before planning; a masked link lint still counts is listed as `in-frontmatter` / `in-code`): frontmatter; fenced code -- backtick and tilde fences whose opener may sit at any indent or inside `>` callouts, and which close only on a line at the **same quote depth**, same fence character, a run at least as long, **at most 3 columns more indent** than the opener and nothing after the run (a quoted fence also ends where its quote ends, so a fence left open in a callout neither swallows nor is closed by a later unquoted fence line; a backtick run whose info string holds a backtick, e.g. ` ```inline``` `, is inline code, not a fence); indented code blocks (4+ columns, tab = 4, not continuing a paragraph -- i.e. after a blank line, an ATX `#` heading, a setext underline, a thematic break, a fence or HTML block, or at the start of the body; tested before the fence opener, so a 4+-indented ` ``` ` after a blank line is indented code; inside a list the threshold is the last item's content column + 4, an approximation reset by an unindented non-item line, fence, HTML block or thematic break, so a list-continuation paragraph stays live); raw HTML `<pre>` / `<script>` / `<style>` / `<textarea>` blocks through the line holding the closing tag; and inline code (paragraph-scoped, so a span may cross a line; a paragraph also ends at a list item start, a thematic break and a setext underline, so a stray backtick never pairs across those). **Not** protected: other raw HTML blocks (`<div>` and friends) and inline HTML -- a link there is rewritten like any other. Exclusions are the default mode's (above): `wiki/log.md` is skipped by design -- it is append-only history, so its alias-only links stay grey as a documented exception -- plus `append_only: true` and `auto_generated: true` pages (in `--alias-only` the flags are re-read on the BOM-stripped text, so a BOM before `---` does not hide them). Their alias-only links are **EXEMPT**: reported, never mutated, broken out per file with lint's split, e.g. `EXEMPT wiki/log.md = 861 (lint ALIAS-ONLY 815, lint BROKEN 46)` (the BROKEN part are dotted / `/` / `:` names lint files under BROKEN). EXEMPT counts only links lint counts: `_meta/` `auto_generated` pages are left out (lint drops them), and so are collision links (lint opens the file of that name) and `lint_hidden` links (lint's code-strip masks them).

```
python scripts/fix_wikilinks.py --alias-only --root PATH --migrate-legacy-state          # 0. legacy in-vault state? dry run of the move
python scripts/fix_wikilinks.py --alias-only --root PATH --migrate-legacy-state --apply  # 0b. move it out of the vault (before any new --apply)
python scripts/fix_wikilinks.py --alias-only --root PATH                       # 1. dry run: plan + manifest, writes NOTHING in the vault
python scripts/fix_wikilinks.py --alias-only --root PATH --apply --max-files 10  # 2a. FIRST apply in a vault: smoke batch, then click-test
python scripts/fix_wikilinks.py --alias-only --root PATH                       # 2b. fresh dry run after the smoke batch
python scripts/fix_wikilinks.py --alias-only --root PATH --apply --batch-size 40  # 2c. apply the manifest in batches
python scripts/fix_wikilinks.py --alias-only --root PATH --restore RUN_ID      # 3. undo an apply (only unchanged files)
python scripts/fix_wikilinks.py --alias-only --root PATH --verify              # 4. exit 0 iff SAFE_REWRITES = 0
```

**Run each `--apply` (and `--migrate-legacy-state --apply`) alone and read its result before the next command** -- never chain another command after an `--apply` in the same shell invocation (`&&`, `;`): its exit code and its STOP / RESTORE lines are the next decision, and a chained command hides them. **One lock-participating fix_wikilinks writer per vault -- enforced by a run lock (ADR-0006 / ADR-0007, regression R161).** Every `--alias-only` run that may write operational state (dry run, `--apply`, `--restore`, `--migrate-legacy-state --apply`, `--rebind-state`, `--forget-state-dir`, and `--verify` or the migrate dry run when given `--state-dir`) holds `run.lock` in the vault's DEFAULT state dir, whatever `--state-dir` it uses; plain `--verify` and the plain migrate dry run take none. After acquiring, a run also refuses (releasing its own lock) when a same-folder-name sibling state key holds a live or unprovable `run.lock`: one directory can be reached under path spellings that hash to two keys (`C:\...` vs `\\localhost\c$\...`), so it may be this vault -- or a different vault with the same folder name, refused conservatively while its run is live. While it is held, any other such run refuses at once (exit 2, nothing written) and names the holder (pid, host, mode, start time, lock id) and whether it is alive. The lock is created complete in one atomic step (a temp record, fsynced, then `os.link`); a file system without hard links is refused, never given a weaker lock. A hard-killed run leaves a STALE lock: on Windows the refusal prints `--alias-only --root <vault> --break-lock` -- a standalone command that removes the lock only when its holder is provably gone (pid not running, or reused by another process) -- then run a plain dry run first. On Windows, `--break-lock` is safe alongside other `fix_wikilinks` runs: it judges and deletes the same `run.lock` object through one exclusive handle, so it cannot delete a live or replacement lock that it did not judge stale (regression R170, ADR-0008). Off Windows, automatic `--break-lock` refuses; remove `run.lock` manually only after confirming no `fix_wikilinks` run is live. A holder that cannot be proven gone (creation time unreadable, another host, a malformed lock) is never broken by flag: delete the file by hand only after confirming no run is live. A failed release keeps the run's exit code and prints `WARNING: operation completed, but run.lock could not be removed`. Backtick-mode `--apply` takes the same lock (ADR-0007, regression R168) -- mutual exclusion and lock recovery only, no manifest, backups or state -- so `fix_wikilinks` operations that can mutate vault pages or shared operational state serialize through one per-vault run lock (one lock-participating writer per vault); its dry run takes none, and where the lock is unreachable (`LOCALAPPDATA` unset, Microsoft Store Python) backtick `--apply` refuses with exit 2. External editors (a human, Obsidian, sync) are outside that guarantee (backtick mode's read-then-write risk: regression R172).

#### Operational state lives outside the vault (ADR-0005, regression R153)

The manifest, the apply logs and the original bytes of every rewritten page are **operational state**, not vault content. They live in a **state directory** outside the vault and outside any sync service -- on the first real Dropbox apply, `os.replace` of an in-vault `apply-log.json` failed with `WinError 5` while Dropbox held the new version open (R153).

- **Location.** Default `%LOCALAPPDATA%\WIKIllm\alias-fix\<vault-folder-name>-<hash8>\` (off Windows only, `~/.local/state/WIKIllm/alias-fix/...` when `LOCALAPPDATA` is unset; on Windows an unset or empty `LOCALAPPDATA` is refused, exit 2 -- a silent fallback would move the index of record and hide every run registered under the real `%LOCALAPPDATA%`, and `--state-dir` does not bypass it; a Microsoft Store (MSIX) Python is refused the same way, because its `%LOCALAPPDATA%` writes are redirected into a private package folder no other interpreter sees -- on many Windows installs `python3` is the Store shim, so run `python -B`), where `hash8` = the first 8 hex digits of sha256 of the resolved vault path, `os.path.normcase`d with `/` separators. It holds `manifest.json`, `vault.json` (which path it belongs to) and `backup/<run_id>/` (page backups, `apply-log.json`, rotated `apply-log.prev-*.json`). `--state-dir PATH` is the ONLY override -- a flag, deliberately not an environment variable. A state dir, its `backup/` tree (e.g. `--state-dir` = the vault's parent and the vault folder named `backup`) or `--manifest` that resolves inside the vault is refused (exit 2, nothing written). The in-vault test compares file-system identity (the path or any existing ancestor IS the vault directory) as well as the resolved text, so `\\?\<vault>\state`, `\\localhost\c$\...\<vault>\state` and similar spellings are refused too, and a `--state-dir` / `--manifest` with a path component ending in a space or a dot (Windows strips it on create) is refused as an unsupported path form. A `\\?\`-prefixed spelling of an outside dir is the same dir as its plain spelling (one registry entry, printed plain). **One state dir belongs to exactly one vault path**: `vault.json` records it, and a `--state-dir` whose `vault.json` names another vault is refused (exit 2, nothing written -- a byte copy of a vault sharing one state dir would get the same run_id and rotate away the original's unfinished apply log); a registered dir that names another vault is not trusted (fail closed). The apply log's per-file `backup` field is relative to the state dir (`backup/<run_id>/<file>`); restore resolves it against the directory the run actually lives in and refuses (`backup-missing`) any backup outside that run's `backup/<run_id>/`.
- **Discovery.** The default dir is the index of record: a run with `--state-dir` registers that dir in `<default dir>\state-dirs.json` (canonical absolute path + `last_used`), creating the dir with its `vault.json` first (even for a write-free `--verify`), so a pointer never names a dir the tool never made. The unfinished-run check and `--restore` search the current state dir, the default dir, every registered dir and legacy in-vault state (`.alias-fix-backup/`); each registered dir is checked to lie outside the vault before it is trusted. A registered dir that is unreachable (or inside the vault, or an unreadable `state-dirs.json`, or a state dir whose `backup/` exists but cannot be listed -- an ACL-denied or failing directory is never read as empty) prints `WARNING: ... cannot prove there is no unfinished run`: `--apply`, `--restore` and `--migrate-legacy-state --apply` fail closed (exit 2), `--verify` fails (exit 1), a dry run proceeds with the warning. Pointers are never pruned automatically: `--forget-state-dir PATH` removes one only after proving that dir holds no unfinished run (an unreachable dir cannot be proven; if it is gone for good, create it empty and re-run). One run keeps one location: `--apply` refuses a run_id that already has apply logs in another location, and `--restore` refuses a run_id found in two.
- **Every dry run / `--apply` / `--restore` / `--verify` prints `STATE: <dir>`**, plus `REGISTERED IN: <state-dirs.json path>` when the state dir is not the default. A dry run writes NOTHING inside the vault (pinned by a before/after hash tree of every file and directory).
- **Identity.** State is keyed by the resolved vault path, so a moved vault does not inherit its old runs. State under the default root for another key with the same folder name is only a warning heuristic: settled runs there warn; an unfinished run there blocks `--apply` / `--restore`. `--rebind-state OLD_PATH` attaches that key's state to this vault, and only when `OLD_PATH` no longer exists -- if it still exists this vault may be a copy, and nothing transfers; afterwards `--restore` accepts apply logs rooted at the old path. The grant (`rebound_from` in this key's `vault.json`) is written BEFORE anything moves, whether or not this key has state yet; a failure after it exits 3 `REBIND INCOMPLETE` and a re-run finishes. A key dir that records another vault (the shape an interrupted rebind leaves) makes every run warn `an interrupted --rebind-state` and fail `--apply` / `--restore` closed until `--rebind-state OLD_PATH` is re-run. **Normal procedure: settle or restore every run BEFORE moving a vault.**
- **Legacy state (legacy in-vault layout: `<vault>\.alias-fix-backup\`, `_meta\alias-fix-manifest.json`).** Every run prints `NOTE: legacy in-vault state ...` while any remains; legacy runs stay discoverable and restorable in place until migrated. `--migrate-legacy-state` is a dry run by default; with `--apply`, for each legacy entry (runs and `<run_id>-inspected` set-asides alike) it copies to a staging name, verifies every file's hash, size and mtime, renames into `<state dir>/backup/`, proves the tool's own discovery finds the run there and classifies it for restore exactly as the source, registers, and only then deletes the in-vault copy (apply logs first: the rotated `apply-log.prev-*.json`, then `apply-log.json` last). A failure before the delete keeps that entry's source (exit 1, `MIGRATION INCOMPLETE`) and removes the unproven copy that invocation renamed into place, so the run stays in one location and its RESTORE keeps working; a copy an earlier invocation made is never removed. A re-run resumes an interrupted delete: a source that has lost apply logs its verified copy still holds (fewer prev logs, or none) was proved before the delete began, so the re-run registers the copy and finishes the delete. A legacy run whose log root is an older path of this vault (the folder was moved after the apply; in place, restore accepts it because the run dir moved with the vault) keeps that acceptance: migration records the run's log roots, bound to this vault, in `backup/<run_id>/migrated-from-vault.json`, so the migrated run still restores with `NOTE: vault moved from` -- and another vault pointed at the same state dir is still refused. The stale manifest is deleted only after every entry migrated, and the run ends `LEGACY STATE: 0 after migration -- zero`. **Run it before the next `--apply` on a vault that has legacy state** -- an apply of a run_id that has legacy logs is refused until then. Retention cleanup of settled runs is a separate, later job.

#### Lock retries and the crash-safe journal (regression R157, ADR-0005 R4 / R5)

Moving the state out of the vault does not by itself make the tool robust: vault pages stay in Dropbox, so every write the tool makes retries a transient Windows lock.

- **Only the three lock codes retry** -- `WinError 5` (access denied), `32` (sharing violation), `33` (lock violation), read from the exception's `winerror`. Anything else fails at once. Backoff is fixed at 0.1, 0.2, 0.4, 0.8, 1.6, 3.2 s (6 retries, 6.3 s at most per operation; every lock measured cleared within 0.26 s -- do not lengthen it). **Reads are the gap:** CPython's `open()` (every page / backup / state READ) reports a real Windows sharing violation as `PermissionError` errno 13 with NO `winerror` (probed with `CreateFileW` share mode 0; only `os.replace` carries `WinError 5`), so under this rule a locked read is never retried. It is never mistaken for a human edit either: apply stops the batch (exit 3 + RESTORE; `read failed for ...`), a write's re-hash read fails the write at once, restore lists the page `restore-read-failed` with `RESTORE INCOMPLETE` (never `changed-since-apply` + SET ASIDE), and the unfinished-run check counts the page live (fail closed). A page that is gone (`FileNotFoundError`) is the only read failure treated as a change.
- **The hash rule re-checked before each retry depends on the write type.** A page write re-hashes its target immediately before its FIRST attempt as well as before each retry -- an earlier lock backoff (this page's backup retry, or earlier pages of a restore, whose plan hashed every page up front) must never widen the check-to-write gap over a human save (apply: `changed-during-apply`; restore: `changed-during-restore`, left alone). A page write retries only while the page still holds its pre-apply bytes; if it already holds exactly the intended output (the refused rename had landed) it counts as written and is never rewritten; anything else is a concurrent human edit -- not written, listed `changed-during-apply`, like the pre-write re-hash. A re-hash read that is itself refused by a lock proves nothing, so it never falls through to a write (page or backup): the tool waits the next backoff and re-reads, on the same retry budget, and a read locked past it stops the batch (exit 3 + RESTORE). A backup is written when absent and kept when byte-identical to the original; any OTHER existing backup is a conflict that stops the batch and is never overwritten. A local state save (manifest, apply log, `state-dirs.json`, `vault.json`) is an atomic replace with the same retry, and the reads of those files retry a winerror 5/32/33 lock too (a transient lock on an apply log must not read as an unreadable log; one that outlasts the retry still fails closed) -- but see the reads gap above: `open()` does not raise those codes for a real Windows read lock, so in practice a locked read fails at once, safely. Restore applies the mirror rule to its page writes (retry only while the page still holds what the apply wrote), and its page and backup reads take the same winerror-only retry (same reads gap: a real locked read is a transient `restore-read-failed` row).
- **When the retry budget runs out, the batch stops cleanly**: no file is skipped for a later one -- the files already written are listed, exit 3 with the `RESTORE:` command, exactly like a failed postcondition. A failed apply-log save stops the same way (`APPLY LOG SAVE FAILED ...`); if the very first write-ahead save fails nothing was written and no RESTORE is printed. Restore follows the same rule (owner ruling 2): at the first page whose write, verify or read stays locked it STOPS -- that page is REVIEW_REQUIRED `restore-write-failed` / `restore-read-failed`, every later page it would have written is `restore-not-attempted` and left as the apply wrote it, the ledger is still saved, and it prints `RESTORE INCOMPLETE: N file(s) ...` with the same `RESTORE:` command; re-running it finishes the job, and a further run shows `RESTORED = 0`.
- **Every `--apply` and `--restore` ends with `LOCK RETRIES: N (max wait Xs)`** (max wait = the longest total backoff any one operation needed). `0` is the normal reading; a nonzero count means the retry absorbed a lock.
- **The journal keeps its write-ahead shape**: per batch an intent save (every file of the batch with pre/post hashes and backup path, before any write), an after-write save and a committed save, plus a final save. Restore reads a page the log still marks `pending` as a restore candidate, so a crash at any point -- before or after any save, after any page -- is exactly undoable: every page of the durable log is accounted for once as RESTORED, ALREADY_ORIGINAL or REVIEW_REQUIRED (with no outside edits REVIEW_REQUIRED is 0), and a second restore reports `RESTORED 0`. A page the apply logged but never wrote (`changed-during-apply`, `backup-failed`) is ALREADY_ORIGINAL while it holds its original bytes, else a `never-written` REVIEW row that does not keep the run from settling.
- **Read a restore's whole result, not the RESTORED line.** The 11-missed-files case (the 2026-09-30 Dropbox repro, regression R157) was a first restore that printed `RESTORED = 297` and also `REVIEW_REQUIRED = 11` with exit 1 -- 11 pages whose own restore rename or read hit a transient Dropbox lock -- but only `^RESTORED|^ERROR` lines were read. The exit code, `REVIEW_REQUIRED` and any `RESTORE INCOMPLETE` line are the result.
- Test hook (temp vaults only, inert elsewhere with a WARNING): `FIX_WIKILINKS_TEST_LOCKS` injects N lock errors per operation -- see the comment at `LOCK_FAULT_ENV` in the script. Never set it in real use.

Every dry run and `--verify` prints three counts, each on its own line:

```
SAFE_REWRITES = N      uniquely determined rewrites this tool will make
REVIEW_REQUIRED = N    links a human must decide (the manifest's review queue)
EXEMPT = N             alias-only links in excluded files, then one line per file:
EXEMPT wiki/log.md = N (lint ALIAS-ONLY a, lint BROKEN b)
```

**REVIEW_REQUIRED and EXEMPT are legitimate end states, not failures** -- review items need a human decision, and EXEMPT is known historical debt in files that are never mutated. They must never be forced to zero, and neither takes part in any exit code or reconciliation. `Nothing to do` is printed only as `Nothing to do: nothing safely auto-remediable remains (review-only findings may remain)`, when SAFE_REWRITES = 0. `--apply` whose manifest has no applicable file while the re-plan finds safe rewrites in files the manifest never listed prints `N safe rewrites in K files not in the manifest -- re-run the dry run. Nothing written.` and exits 6 -- an empty or stale manifest never masks pending work (review h1-I1-1). The same holds when the manifest DOES have ready files: they are applied, each unplanned file is listed with its link count, and the apply ends with the same `re-run the dry run.` line and exit 6 (review h3-R3-I1-unplanned-exit0).

1. **Dry run** prints per-category counts, the three counts above, the first 25 review items and the predicted lint ALIAS-ONLY count (safe + review + EXEMPT links lint files as alias-only), and writes the manifest to `<state dir>/manifest.json` (`--manifest PATH` overrides; it too must be outside the vault) -- nothing inside the vault. Provenance: `schema_version`, `mode`, normalized absolute `root`, `tool_sha256` (plus `tool_git_commit`, or null outside a git checkout), `generated`, the exclusion lists and the `edit_deny` set, `planned_links` (LINK edits) and `planned_files` (file count) as separate fields, per-category totals, per-file EXEMPT splits, per-file sha256 + exact edit list (each edit carries the `lint_kind` lint gives the original link), the full review queue and broken targets. The review queue is the human's work list -- read it there, not from the console.
2. **`--apply`** rejects (exit 2, nothing written) a manifest whose `schema_version`, `mode`, `root` or `tool_sha256` differ from this run -- a changed script means re-run the dry run -- or whose `planned_links` / `planned_files` disagree with its own file list and the re-plan (stale files excepted). It re-plans and writes only files whose sha256 **and** edit list still match; a file changed or new since the dry run is listed with its link count as REVIEW_REQUIRED and not written -- re-run the dry run to pick it up. Files go in batches (`--batch-size`, default 40). **Smoke batch** (`--max-files N`, only with `--alias-only --apply`, N >= 1): the first apply in any vault writes only the first N applicable (ready) files in the manifest's sorted file order -- still backed up, batched, postcondition-checked and lint-reconciled -- and the apply log records `result: partial` (deliberate and settled: the unfinished-run guard never blocks on it, and `--restore RUN_ID` undoes it like any apply). Its identity is `manifest_safe_rewrites = links_applied + links_skipped_stale + links_deferred` (deferred = the links in the ready files past N). It ends with `SMOKE: N files applied; click 2-3 rewritten links in Obsidian, then re-run the dry run and --apply for the rest.` -- or, only when nothing is left anywhere (N covered every ready file AND no file is stale since the dry run, changed during the apply or unplanned), `SMOKE: N files applied (all ready files; nothing left to apply); click 2-3 rewritten links in Obsidian, then --verify.`; when no file was written at all, `SMOKE: 0 files written; re-run the dry run.`; when the apply exits nonzero after the batches (lint reconciliation / identity / unplanned files: rc 4, 5, 6), `SMOKE: apply did not verify (rc N) -- do not click-test or continue; ...`, while a failed batch (rc 3) prints the RESTORE block instead and no SMOKE line (review g2-R2-C1-hint-nothing-left, arb-readme-smoke-fail-rc3) -- and lists the written files (`smoke-applied <file>`) so the owner knows where to click. Re-running `--apply` on the SAME manifest after a settled smoke batch lists the smoke files as `written-by-earlier-apply` (settled, counted as `links_previously_applied`, not rewritten) and prints a NOTE that `--restore RUN_ID` now undoes both applies together; only when the earlier apply of the run is unfinished is the label `restore first` and the apply refused (exit 2). The manifest is then stale for those files by design: run a fresh dry run (new manifest, SAFE_REWRITES = the remainder) and a full `--apply`; both exit 0. **Write-ahead apply log** `<state dir>/backup/<run_id>/apply-log.json`: before a batch is written, every file in it is logged with `pre_apply_sha256`, `post_apply_sha256` and its backup path (state-dir relative); the original is copied to `<state dir>/backup/<run_id>/` (an existing backup is reused only if it is byte-identical to the original; any other existing backup is a conflict that stops the batch) and the file is re-hashed immediately before its write -- one edited since the plan (a human, Dropbox) is listed `changed-during-apply` and left alone. Writes are temp-file + rename. A table is never reshaped: a link on a table HEADER row with a bare `|` separator (escaping it would change the header's cell count and unmake the table) is held `table-header-bare-pipe`, a table link whose display holds its own bare `|` is held `odd-form`, and a file whose planned rewrites would change which lines are GFM table rows is held whole (`table-structure-changed`). After each batch a recount must show the alias-unique drop equal to the edits applied, the table rows of every written file unchanged, the canonical count risen by exactly that many (an alias drop alone is also what a rewrite swallowed by a code span looks like), and no rise in broken links. A failed postcondition -- or a recount that cannot re-read a batch file, a write the OS refuses (a Dropbox / antivirus lock that outlasted the lock retry, or any non-lock error), a backup that fails or conflicts, or an apply-log save that fails -- stops with exit 3: later batches are untouched, the failing batch STAYS WRITTEN, and the tool prints the committed batches, the failing batch's files, the backup directory, the reconciliation with its failure terms and a copy-paste `RESTORE:` command. Every completed apply prints the identity `manifest_safe_rewrites = links_applied + links_skipped_stale` (plus `+ links_deferred` on a smoke batch) and exits 5 if it does not hold, then **reconciles with lint**: it runs the sibling `lint.py --summary` before the first batch and after the last, and lint's ALIAS-ONLY drop must equal the applied links lint filed as alias-only and its BROKEN drop the applied links lint filed as broken (dotted / `/` / `:` names); any difference exits 4 with the reason. No `lint.py` beside the fixer (or a lint too old to print the ALIAS-ONLY line) prints `LINT RECONCILIATION: NOT MEASURED` -- never a silent pass; a lint measured before the writes that crashes, times out or prints nothing parseable after them prints `LINT RECONCILIATION FAILED: NOT MEASURED after the writes` with lint's exit code and stderr tail and exits 4 (review h2-I9-lint-after-unmeasured-exit0). Writes are temp-file + rename and a failed write or rename removes its `<file>.md.tmp-alias-fix` (h2-R2-TMP-LEAK). The backups live in the state dir, outside the vault and outside Dropbox (ADR-0005); retention cleanup of settled runs is a separate, later job.
3. **`--restore RUN_ID`** (`--alias-only --root PATH --restore RUN_ID`; also printed as `Undo:` after every apply) is concurrency-safe: a backup is copied back only when the file's current hash equals the recorded `post_apply_sha256` AND the backup's own hash equals `pre_apply_sha256`. A file edited since the apply, or a corrupted / missing backup, is reported REVIEW_REQUIRED and left untouched -- newer work is never overwritten. When RESTORE cannot settle a run (REVIEW_REQUIRED remains: backup missing/corrupt, an unreadable rotated log, or you choose to keep the written page), fix or accept the listed files by hand, then rename `<state dir>/backup/<run_id>` to `<run_id>-inspected` (or move it out; for unmigrated legacy state the run dir is `.alias-fix-backup/<run_id>`) -- the `SET ASIDE:` line names the exact directory; the unfinished-run guard skips it from then on. RESTORE prints this as a `SET ASIDE:` line whenever it ends with such rows (a `restore-write-failed` lock alone is transient: re-run instead), and the dry run / `--apply` / `--verify` repeat it after the `RESTORE:` line once a restore of that run has left review rows (review t2-DS1-unsettleable-live-run). A file the OS refuses to write after the lock retry (Obsidian / Dropbox / antivirus lock) is REVIEW_REQUIRED `restore-write-failed` (`restore-read-failed` for a page or backup it could not read) and the restore carries on through the other files, still writes its ledger and prints `RESTORE INCOMPLETE:` with the command; re-run it once the lock clears (h2-R2-RESTORE-LOCK). If the ledger itself cannot be saved the restore exits 3 saying so (the listed files ARE restored; re-run to record it). Restore also removes any leftover `<file>.md.tmp-alias-fix` beside a logged file. Prints `RESTORED` / `ALREADY_ORIGINAL` / `REVIEW_REQUIRED` and `LOCK RETRIES`; exit 0 iff nothing needs review -- read the exit code and all three counts, never RESTORED alone (the 11-missed-files lesson above). A run id must be 16 hex digits. Restore reads EVERY apply log of the run -- `apply-log.json` plus each `apply-log.prev-*.json` a re-apply rotated aside -- so a file any apply of that run wrote is covered by the one printed command (a current hash equal to any logged `post_apply_sha256` is restorable; logs that disagree on `pre_apply_sha256` send the file to review). An unreadable `apply-log.json` still refuses the restore; an unreadable rotated prev log no longer does -- the readable logs are restored and the prev log is a REVIEW_REQUIRED row (`unreadable rotated apply log`), so the run stays unsettled until set aside (review t2-DS1-printed-restore-refuses). The same-run_id `--apply` check skips an unreadable prev log with `NOTE: unreadable rotated log ... skipped` when the current log is settled, and otherwise refuses with `RESTORE:` and `SET ASIDE:` lines (review t2-DS1-same-rid-corrupt-prev-silent-wedge). Re-applying the same manifest labels a file still holding what an earlier apply of the run wrote as `written-by-earlier-apply` (reconcile term `links_previously_applied`), not `stale-since-dry-run`; while that earlier apply is unfinished (failed batch or crash: `result` not one of complete / partial / restored) and such files remain, `--apply` refuses -- exit 2, nothing written, no log rotated -- and prints the `RESTORE:` command to run first (review h1-I8-1 / h1-R1-1 / arb-I8-2). The guard also spans run ids (review h3-R3-DS-1): a failed apply's files have changed, so the next dry run issues a NEW run_id; the dry run, `--apply` and `--verify` therefore scan every `backup/*/apply-log.json` in every discovered state location (current, default and registered state dirs, plus legacy `.alias-fix-backup/*/`), and while any unfinished apply still has files exactly as it wrote them the dry run prints `WARNING: unfinished apply <run_id> ...` with that run's `RESTORE:` command, `--apply` refuses (exit 2, nothing written) and `--verify` exits 1. That scan reads only each run's current `apply-log.json` (a corrupt rotated `apply-log.prev-*.json` blocks nothing), skips a run whose `result` is `complete`, `partial` (a finished `--max-files` smoke batch) or `restored` -- a restore that ends with REVIEW_REQUIRED = 0 writes `result: restored`, settling the run -- and never counts a file whose bytes a LATER complete apply of any run also records as its post hash (review t1-DS1-a: without this, a later run's legitimate write was offered to the old run's RESTORE and reverted). A run whose current `apply-log.json` is unreadable is reported separately (`WARNING: apply <run_id> has an unreadable log; its files cannot be checked`, `VERIFY FAIL: N apply run(s) have an unreadable apply log`, no `RESTORE:` line, since `--restore` refuses such a log): inspect the run directory the warning names, put back by hand any page still holding that apply's edits, then rename the directory to `<run_id>-inspected` (or move it out of its `backup/` dir) and the scan skips it (review t1-DS1-b). A vault folder moved or renamed after an apply still restores: when the log's `root` differs from `--root` but the run directory is legacy state inside `--root` (review arb-M1-moved-vault-wedge), or the state was attached with `--rebind-state` from that root (ADR-0005), restore prints `NOTE: vault moved from <old root> ...` and proceeds on the per-file hash gates; any other root mismatch is refused. The restore prints `Run: <run dir>` naming where it found the run.
4. **`--verify`** re-plans without writing and exits 0 iff SAFE_REWRITES = 0, whatever REVIEW_REQUIRED and EXEMPT are; review and broken counts are printed as the residual. Then re-run `lint.py`: ALIAS-ONLY equals the review items whose `lint_kind` is `alias-only` plus the EXEMPT links lint files as alias-only (the per-file `lint ALIAS-ONLY` numbers) -- exact, with no hand-subtracted classes: collisions carry `lint_kind` `canonical`, lint-hidden items `masked`, and dotted / `/` / `:` names `broken`. The residue classes are exactly: ambiguous aliases, collisions, held links (with their `reason`: unsafe slug, self-check, `lint-mangled-slug` (the holder's own filename is one lint files as BROKEN or GHOST -- a dotted slug, a `/` / `:` slug, or `date` / `published` -- so the rewritten link would not reconcile), in-frontmatter, in-code, path-form, out-of-scope file, lint-hidden, and `lint-only (code-strip join)` -- a link that exists only after lint's code-strip deletes a span, e.g. [[Soil p`x`H]] read by lint as [[Soil pH]]), and EXEMPT links in `wiki/log.md` / `append_only` / `wiki/` `auto_generated` pages. `lint_hidden` links: lint's code-strip pairs a mid-line ` ``` ` as a fence (CommonMark and Obsidian require a fence opener to start the line), so lint does not count a link the fixer and Obsidian see live; such links stay grey and are queued `lint-hidden`. Also pre-existing (predates R151): a link to an off-inventory page (`raw/`, `templates/`) that no page carries as an alias is canonical to the fixer (never rewritten) but BROKEN to lint -- follow-up beside the dotted-name mangling and R150 cases.

## tests/ -- frozen benchmark for the LLM link suggester (template-only)

## sync_from_template.py — pull shared tooling from the WIKIllm template

Every wiki instance shares this scripts/ toolset and the `.claude/skills/ingest` skill; the template repo is their upstream. This script SHA-256-compares the shared set against the template and (with `--apply`) copies drifted/missing files in.

```
python scripts/sync_from_template.py            # drift report (dry-run)
python scripts/sync_from_template.py --apply    # pull template versions in
```

Trusted template path: `WIKILLM_TEMPLATE` environment variable, default `~/.wikillm/template`. Set it to your clean upstream checkout. `--template PATH` selects a source; a different source requires `--allow-noncanonical`. See `SETUP.md`. Never touches instance-owned content (`CLAUDE.md`, `wiki/`, `raw/`, topic-specific scripts, and all of `_meta/` EXCEPT the two fleet docs in SYNC_SET: `_meta/fleet-conventions.md` and `_meta/book-scanning.md`, regression R27). If you've improved a shared script locally, **back-port to the template first**, then re-sync — otherwise `--apply` overwrites your improvement. A fleet doc that differs locally is guarded: `--apply` refuses until you diff it and either back-port or pass `--adopt-meta` (a differing `_meta/` doc is pre-adoption instance content or a local edit worth keeping -- never silently overwritten).

**The source gate (regression R38):** `--apply` refuses unless the template working tree provably IS reviewed content -- configured trusted path (`--allow-noncanonical` for a deliberate alternate source/test use), checked out on `main`, `main` exactly at `origin/main` (ahead = unreviewed local commits; behind = would downgrade vaults), SYNC_SET paths committed, no merge/rebase in flight. The copy itself is transactional: staged to `.sync-tmp`, endpoint-re-verified (template AND destinations), installed with `.sync-bak` rollback, all under a `.sync-lock` at the vault root. A refusal names exactly what to fix. A leftover `.sync-bak` after a crash is treated as precious (it may be the only copy of a pre-sync file) and blocks syncing until inspected; concurrent edits to destination files abort the sync with the user's bytes preserved. Dry-run reports the same problems as warnings without refusing.

**The pycache sweep (regression R119):** a successful `--apply` -- including one with nothing to copy -- deletes the vault's `scripts/__pycache__` (regular files only; a `__pycache__` that is itself a symlink or junction -- detected via `lstat` reparse-point attributes, so it holds on Python < 3.12 too -- is refused, and a non-file entry inside is left alone; both are named in a WARNING) and prints `pycache : swept N files` (`swept 0 files` when there is none). A dry run prints `pycache : would sweep N files` plus one `would sweep:` line per file and deletes nothing. A refused `--apply` sweeps nothing. A vault still running an older copy of this script is swept on its SECOND `--apply` (the first installs the version that sweeps) -- one reason to run the sync twice per vault. The sweep clears residue; the `sys.dont_write_bytecode` guard (see `_wikilib.py` above) stops new residue.
