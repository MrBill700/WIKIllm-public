# Ingest — the raw-inbox loop

This wiki's core workflow. One named entry point for: detect -> ingest -> accept -> verify.

## 0. Orient (skip if already oriented this session)

1. Read `CLAUDE.md`; if this is your first session in this vault, also read `_meta/llm-wiki.md`.
2. Read `_meta/open-loops.md` — clear anything due before opening new work.

## 1. Detect

```
python scripts/check_raw.py --summary
```

Never rely on `ls` timestamps or memory. If the report is empty: say so, run step 4 only if other work happened, and stop.

## 2. Ingest (one source at a time, human in the loop)

For each added/modified file, in the order the user cares about (ask if unclear):

- **Probe size before reading.** For anything big (PDFs, exports, transcripts, single-line dumps): read page-ranged (`pages` param) or excerpt — never pull a whole large file into context. `.epub` chapters go through `scripts/extract_chapter.py`.
- Discuss key takeaways with the user before writing pages.
- Write/update pages per CLAUDE.md conventions: one `sources/` page (with locators for load-bearing claims), ripple updates to `entities/` and `concepts/`, an `index.md` entry, a `log.md` entry.

**The locator rule is blocking, not aspirational.** Every load-bearing claim gets a verbatim quote with a page/section/timestamp reference on the `sources/` page, and every page that cites it links to that anchor (`[[sources/slug#Locators...]]`). Load-bearing means: any figure, dose, threshold, date, named finding, or claim another page will build on. **If you cannot locate it in the source, you cannot assert it** -- downgrade it to an explicit hedge naming what is unverified, or leave it out. Do not paraphrase from memory of the document you just read; go back and quote it.

Why this is the one rule to hold: a 2026 audit found locator coverage at **11%** in a mature instance, and every defect class found in a full re-read clustered on the unanchored claims. An anchored claim can be re-checked in seconds; an unanchored one requires re-reading the whole source, so in practice nobody ever does, and the drift compounds silently. `scripts/audit_claims.py` reports coverage against a target on every close-out.

Two write-time corollaries (from the 2026-07 backfill sessions -- retro-anchoring cost ~80% of a session that should have spent that time judging claims):
- **Write the `#heading` fragment the moment you write the citation.** The source page is open in front of you; matching the heading costs seconds now vs. minutes-per-claim for whoever backfills later (`scripts/suggest_anchors.py` mechanizes the backfill, but write-time is still ~free).
- **Design sources-page headings to be anchor-worthy**: distinct, descriptive headings per content cluster ("What it corrects", "The fungibility insight") make every anchor self-explanatory; a page whose only citable heading is "Key takeaways" forces every claim to share one blunt anchor. Never put a wikilink inside a heading -- it can't be anchored to cleanly (nor `` [ ] | # ^ ` \ ``, which break the link syntax). **`*` is fine**: asterisk emphasis in a heading is safe, because Obsidian strips it when matching an anchor -- so the shared source-page shape's `## What's *particularly* useful for ...` is anchorable, and `suggest_anchors.py` writes the anchor with the asterisks removed. (Confirmed 2026-08-09 by clicking one in Obsidian; before that, `*` was on the banned list on the assumption it broke resolution, which made ~7 headings per vault needlessly unanchorable. Do NOT "normalize" emphasis out of existing headings -- there is nothing to fix.) The real hazard is a *substituted* character, not an omitted marker: see the em-dash lesson below.
- **Keep the quotes in their own section.** `suggest_anchors.py` only proposes an anchor mechanically when the winning section is *verbatim* -- mostly the source talking (a `Locators` section, a run of `> [!quote]` blocks) -- because backtesting showed the confident wrong picks were all wiki-voice synthesis sections ("Bearing on positions", "Key takeaways") that the claim was paraphrased *from*. A sources page whose quotes are scattered through prose gets no mechanical backfill. Bookkeeping sections (`See also`, `Links`, `Wiki edits prompted by this source`) are never anchor targets at all.
- Sensitive specifics (account numbers, SSNs, private details) live on `entities/` pages only — and only if the user hasn't excluded them.

Then accept **exactly what was ingested**:

```
python scripts/check_raw.py --accept "exact-file-name.pdf"
```

(`--accept-all` only when every detected change is ingested. Bare `--accept` is invalid.)

## 3. Repeat

More files pending? Back to step 2. The user often drips files in mid-session — re-run step 1 when they say they've added something.

## Fast-capture mode (optional — for clearing a backlog)

The default (step 2) is deep and serial: read, discuss, write the `sources/` page AND ripple into concepts/entities/positions, one source at a time. Right for a few high-value sources; slow when a backlog of dozens of stubs needs to become queryable. **Fast-capture splits ingestion into two speeds** — the corpus goes queryable fast, deep synthesis is deferred to where it earns it.

- **Capture (fast, parallelizable).** Fan out one subagent per source. Each reads its file (pdfplumber for text-heavy PDFs; page images only when a figure/table is load-bearing) and **returns** a drafted `sources/` page — summary + key takeaways + verbatim locators + a "Bearing on positions" steelman. For a handful of sources, the orchestrator writes the files (agents return, you write — keeps frontmatter/tags consistent and lets you dedupe); for dozens, run it as a Workflow swarm instead (see below). Tag each captured page `needs-synthesis`, NOT `to-ingest`.
- **Synthesize (deep, deferred).** Later, per captured source: fold its "Bearing on positions" into `analysis/positions-register.md`, ripple into `concepts/`/`entities/`, then **remove the `needs-synthesis` tag**. That tag IS the deep-work queue.

Three tag-derived states: `to-ingest` (untouched) → `needs-synthesis` (captured, queryable, deep work pending) → ingested (no state tag). A `data/sources.base` view over `file.hasTag("source")` renders them as a live checklist (see "Structured data & Bases" in CLAUDE.md).

**At scale — the Workflow swarm.** For dozens of stubs, orchestrate capture as one background `Workflow` (one agent per source) rather than hand-fanned `Agent` calls. Both capture modes share one scratchpad: before launching workers, the coordinator assigns distinct source slugs and, for sources with multiple workers, unique worker/slice IDs. Single-worker sources may use `<slug>_<step>.*`; multi-worker sources MUST use `<slug>_<worker-or-slice>_<step>.*` or isolated per-worker directories. Workers must never share an output path. Require re-extraction immediately before the final quote check (see Lessons). Three things that bit a real run:
- **Agents write their own pages.** Workflow scripts have no filesystem access, so the "orchestrator writes" rule inverts — each agent `Write`s its own `sources/<slug>.md`. Distinct paths = no conflict; keep frontmatter consistent by pinning the exact template in the prompt, and tell each agent to touch ONLY its own page (never `index.md`/`log.md` — reconcile those yourself after).
- **Inline the source list; don't pass it via `args`.** A complex `args` object can silently fail to bind (symptom: the workflow finishes in ~200 ms having spawned 0 agents). Put the `{slug, glob, angle}` list in the script body.
- **Resolve each file by an ASCII glob, not its exact name.** Filenames with spaces, `&`, or non-ASCII (e.g. a U+2011 hyphen) break exact-path passing; hand each agent a `raw/Pattern*` glob and let it resolve its own file.

**Guardrails.** Fast-capture trades step 2's "discuss before writing" for a **review-after gate** — skim the batch before trusting it, and keep full deep-synthesis rigor for the positions register (the epistemic core). **Triage first:** deep-capture load-bearing papers, give reference docs a one-line `sources/` page, drop non-sources. Capture surfaces reality (mislabeled files, wrong values, missing sources) — read what the agents return, don't rubber-stamp.

**Normalize + reconcile the batch before trusting it**. Agents produce wrong link forms (absolute `wiki/...` paths, HTML entities, links to non-wiki slugs) -- fix every wikilink to correct relative bare form. And each agent sees only its own file, so a "missing document" or contradiction claim may be resolved by another agent's source -- cross-check claims across the batch. In return-then-write mode, do both before writing the files; in the Workflow swarm (agents write their own pages), do it as the review-after pass on the written pages.

## 4. Close out (the CLAUDE.md session close-out protocol)

1. Propagate ripples now, or ledger them in `_meta/open-loops.md` — never as "not yet done" prose.
2. Bump `updated:` on every touched page; write the `log.md` entry.
3. Run the scanners:
   ```
   python scripts/lint.py --summary
   python scripts/check_stale.py --summary
   python scripts/audit_claims.py --n 5
   ```
   Any nonzero broken/orphan/overdue count -> re-run that scanner WITHOUT `--summary` and resolve or consciously defer each item.

   A nonzero ALIAS-ONLY count, and orphans whose only inbound links are alias-only, are fixed by `python scripts/fix_wikilinks.py --alias-only`, not by hand: run the dry run and REPORT its SAFE_REWRITES / REVIEW_REQUIRED / EXEMPT counts; run `--apply` ONLY on the owner's explicit go in this session; the FIRST apply in any vault is a smoke batch (`--apply --max-files 10`); the owner clicks 2-3 rewritten links in the listed `smoke-applied` files in Obsidian and reports in this session that they resolve; only then a fresh dry run and the full `--apply`. Run each `--apply` ALONE and read its result before the next command -- never chain another command after an `--apply` in the same shell invocation. Read an `--apply` or `--restore` result in FULL -- exit code, REVIEW_REQUIRED, any STOP / RESTORE / `RESTORE INCOMPLETE` line -- never only the RESTORED count (regression R157: `RESTORED = 297` had hidden `REVIEW_REQUIRED = 11`); the closing `LOCK RETRIES: N` line is informational (transient cloud-sync locks retry automatically). The fixer's manifest, apply logs and page backups live OUTSIDE the vault (ADR-0005: `%LOCALAPPDATA%/WIKIllm/alias-fix/<vault>-<hash8>/`, printed as `STATE:` on every run; a dry run writes nothing in the vault); if a run prints `NOTE: legacy in-vault state` (the legacy `.alias-fix-backup/` + `_meta/alias-fix-manifest.json` layout), run `--migrate-legacy-state` and, on the owner's go, `--migrate-legacy-state --apply` BEFORE the next `--apply`. When it is unclear whether this vault's click test has already passed, run the smoke batch again (still only on the owner's go in this session) -- it is cheap and settled (result: partial). Its REVIEW_REQUIRED and EXEMPT (`wiki/log.md`, append_only pages) residue is legitimate -- never force either to zero; never add a bare `[[alias]]` link to clear an orphan -- it earns no credit. Expect ORPHANS to jump on the first lint run after the regression R151 sync (a scratch copy of one large vault: 29 -> 308) because alias links stopped counting as inbound; run the fixer's DRY RUN (and --apply only per the gate above) before triaging them -- an orphan whose only inbound links are alias-only is the fixer's job, not a triage item.

   `audit_claims.py` is the faithfulness layer and it belongs **here**, in the loop that actually runs, not only in a quarterly ritual -- it sat unrun for months in every instance while it was quarterly-only. Two outputs, both act-on-able in minutes:
   - **Locator coverage vs target.** If it is below target, the fix is to anchor the claims you touched *this session* -- not to schedule a project.
   - **A 5-claim risk-weighted queue.** Judge each FAITHFUL / DRIFTED / UNSUPPORTED / STALE against the `sources/` page and then the `raw/` document. It ranks by no-locator, stated figures, per-vault priority terms (`_meta/audit-priority.txt`), central pages and bold emphasis, so the five it hands you are the five most worth checking. Fix drift immediately -- then grep the vault for the source slug and sweep every citing line, since correcting the `sources/` page alone leaves stale citations reading as *verified*. The queue consults the judged-claims ledger (`_meta/claim-audit-ledger.json`, regression R52 -- this close-out is its first consumer, regression R117): claims judged FAITHFUL this quarter are skipped, so the five are the five highest-risk claims not yet cleared. Record every verdict you reach with `python scripts/audit_claims.py --record-verdict <id>=<VERDICT>` (the `id=` token ends each queue line) BEFORE you fix the line -- a fixed line is a new identity, so recording after the fix reports that id UNRESOLVED (harmless: the edited line is unjudged and returns on its own); unrecorded, the next close-out re-serves the same five; force one claim you have reason to doubt back in with `--include FILE:LINE` (`--include-judged` reopens every judged claim -- the quarterly deep audit uses it). Log hits as `lint | claim audit (seed, n, hits; split S, unconfirmed U; escalated E/N (reasons: k1=n1, k2=n2))` -- a single in-session read has `split 0, unconfirmed 0; escalated n/a` (the shape's single source is the script's NEXT STEPS block).

   Judge against the **primary**, never against the wiki page that cites it. "Absent from our source page" is not "absent from the literature" -- that inversion has produced real retractions of true claims.
4. **Skill-edit gate.** Ask explicitly: did anything this session reveal a failure mode this skill file should already have caught? If yes and it's a **repeat** -- the same class of mistake surfacing a second time, not a one-off -- draft a `Lessons` entry now, in the section's existing format (a bolded one-line rule + a concrete evidence parenthetical), and add it below -- **then back-port it to your template in the same session** -- your own fork or clone of the template, written `<your-template-repo>` here: a commit there, or `gh issue create --repo <your-template-repo>` with the drafted text as the issue body. With no template repo configured, record the back-port in `_meta/open-loops.md` as a due item. Issue bodies on a public repo are public: strip vault content and personal details first. This file is fleet-synced: a lesson that exists only in this vault's copy is destroyed without warning by the next `sync_from_template.py --apply`, and a protective note in *this* vault's `_meta/open-loops.md` is invisible to the session that runs the sync from another vault. **An ahead copy plus a ledger note is not a safe state** -- back-port first, always. (regression R71: the 2026-09-13 heredoc lesson was added to one vault's copy and guarded by exactly such a ledger line; by 2026-09-16 the lesson was gone, no vault or the template had it, and the note had been reading as current the whole time.) A single occurrence is not yet a validation signal: name it in the close summary instead, and only promote it to a rule once it recurs. This is the same trajectory -> edit -> validate loop the `Lessons` section already runs by hand; the gate just makes the check explicit instead of leaving it to whether you happen to remember to look back.
4b. **Fleet-improvement gate -- file it, do not fix it.** The skill-edit gate above catches lessons about *how to ingest*. This one catches everything else the session tripped over and routed around: a scanner reporting a false positive, a convention the docs no longer describe, template work stranded where it can be lost, a check that silently does not cover what it claims to. These reliably go unrecorded, because at the moment they surface they are a distraction from the ingest, and by close-out they are forgotten.

   Anything affecting the **template or more than one instance** becomes an issue on `<your-template-repo>` (your own fork or clone of the template) -- `gh issue create --repo <your-template-repo> -t "..."` (use labels available in the project), runnable from the vault without changing directory. When no template repo is configured, record it in `_meta/open-loops.md` instead. **Issue bodies on a public repo are public**: strip vault content and personal details before filing. **Vault-specific content debt is NOT this**: a mis-anchored citation, an unwritten page, a question for a human reviewer, all stay in this vault's `_meta/open-loops.md` or `_meta/open-questions.md`.

   **Offer; do not fix.** Fixing here is how a close-out becomes a second session. But write the issue *body* now, while the session still holds the evidence -- that body, not the `gh` call, is the expensive part and the reason the item is still actionable weeks later. Surfacing these is the assistant's job; the user should not have to remember to ask.
5. One-line close summary to the user: what changed + what's deferred (with trigger dates).

## Rules

- **Forgot what the tooling can do? `python scripts/help.py`.** It generates the map by reading the scripts' own docstrings and argparse definitions, so it cannot drift from what is actually installed. `help.py <name>` for one script (prefix match is enough -- `help.py audit` finds `audit_claims.py`), `--full` for every flag, `--recipes` for the command sequences. Point the user at it rather than reciting flags from memory.

- **Never truncate-pipe the scanners** (`| head`, `| Select-Object -First N`): use `--summary` or capture the complete output to a file. Keep file writes in separate commands and verify them before running scanners.
- These scripts always exit 0 by design, with one exception: `lint.py` exits 1 with a one-line message and deliberately NO traceback when `scripts/_wikilib.py` is missing, corrupt, or too old to export the link surface it parses links with (regression R80) -- the message names the remedy, `python scripts/sync_from_template.py --apply`. Any OTHER nonzero exit is a real crash: read the traceback, don't retry blind.
- Tracker pages are declared with `tracker_page: true` in their frontmatter; script-generated pages carry `auto_generated: true` and are never hand-edited.

## Lessons

- **Some sources are claims to *verify*, not content to *summarize*.** When a source is a plan/decision drafted *without* its underlying data (e.g. a plan drafted from memory rather than from the underlying records), ingest becomes **review-then-fold**: run a corpus-review pass first -- a multi-lens Workflow with adversarial verification scales it -- to catch where the source contradicts, ignores, or under-specifies what the wiki already establishes, and **corroborate each load-bearing figure against connected live data** (a connected data source or the raw data files) before hardening it into a page. 

- **When a source cites another work for a load-bearing claim, verify by full-document search before repeating it.** Obtain the cited work and search the *whole* text rather than the cited pages -- reprints and PDFs rarely carry the original pagination, so a whole-document search both moots the page-mapping problem and can prove absence. Record the term counts on the `sources/` page. **And search every typographic variant of a numeric range before writing an absence verdict** -- publishers typeset ranges with en dashes, so the hyphen form you naturally type can return zero on the very page that states the figure. Search `X-Y`, `X--Y` (en dash) and `X to Y`.  

- **Case is a variant too -- and a mechanical verbatim checker is only as good as its normalizer, so regression-test the normalizer before you publish its count.** Fold case, dash spacing, markdown emphasis and any glyph the extractor drops before judging a span absent. But every loosening cuts both ways: a normalizer relaxed once per false MISS eventually passes the very defects it exists to catch, so before stamping an "N/N verified" figure on a page, re-run the **known-bad** spans through the *final* normalizer and confirm they still MISS. (Example: gating a book's quoted spans against its text, eight apparent misses were artifacts of the comparison; **three were real** -- a meaning-altering splice, a word inserted inside quotation marks, and a truncation. Re-running the three **pre-fix** spans through the final normalizer confirmed all three still MISS, which is the only thing that made "31/31" a certification rather than a self-fulfilling artifact.) **Corollary for writing, not checking:** if the source renders a term as a glyph or image, spelling it out in ASCII *inside* quotation marks produces a "verbatim" quote that returns **zero hits in its own source** -- mark it as an editorial substitution instead (`[VO2max]` where the book prints a V-dot and the extractor emits `O 2 max`).

- **Index a large PDF by keyword before reading any of it -- after checking it HAS text.** Step 2 says don't pull a whole large file into context; the cheap way to honour that is to extract per-page text with PyMuPDF/pdfplumber, build a keyword -> page map, then read only the hit pages. (A 62-page 1898 bulletin, a 175-page dissertation, and a 744 KB OCR dump each collapsed to 3-5 targeted reads -- and the keyword counts themselves became the evidence for the full-document-search lesson above.) **First check text coverage PER PAGE -- `[len(p.get_text()) for p in doc]` -- not as one document total:** a hybrid PDF (OCR on some pages, cover text, headers) passes a document-level sum while its substantive pages are image-only, and the keyword map then returns confident false absences. Char counts are a ROUTING heuristic, never a coverage certificate: sparse pages (under ~200 chars -- header/footer-only) and image-bearing pages route to the render path, but the only thing that certifies search coverage is EYES ON RENDERED PAGES -- if any page is scan-suspect, run the contact-sheet pass over the whole file (it is cheap) and let the sheets, not the counts, tell you which pages the text layer actually covers. No unrendered page is declared searchable from its char count alone, and a keyword visibly present on a rendered page that returns zero map hits means the text layer lies for that page. For scanned pages, "indexing" means a two-pass render-and-read: (1) render every page ~1100 px, tile 4-up into contact sheets, read the sheets for a page-by-page map (74 pages became 19 images at ~quarter the token cost); (2) re-render ONLY the pages you transcribe at ~1700 px single-page -- contact-sheet resolution locates a table but cannot carry dense notation. **Renders an agent makes while reading a source go to a temp dir, never into `raw/`** -- the carve-out and its reasoning are in `_meta/fleet-conventions.md` ("What belongs in `raw/`"), which is also what keeps human page scans and capture-script output legitimately in `raw/`; a render written beside the primary becomes a pending ADDED file that no ingest will ever account for . Two scan hazards: pages arrive rotated (check before reading), and photographed tables skew so row labels drift against cells -- resolve alignment with an independent structural check (a fact the prose asserts that only one alignment satisfies), and flag unreachable values as uncertain rather than asserting them. 

- **A source page that renders fine may be a transclusion stub, and "not online" is usually untested.** Wikisource book/article pages often contain only `<pages index=... from=X to=Y />`; the article URL returns a truncated render and `?action=raw` returns the stub. Fetch the underlying `Page:<scan>.djvu/<n>` pages individually via `?action=raw`, locating them with the MediaWiki search API. Likewise, when web search is unavailable or a work looks unobtainable, query repositories directly -- `archive.org/advancedsearch.php` and `/metadata/<id>` surfaced a complete 744 KB administrative history when only one chapter had been to hand.

- **MediaWiki-family sites (Fandom, wikis behind Cloudflare) 403/402 the extraction tools -- skip the rendered page and curl the raw endpoint.** On riordan.fandom.com the defuddle CLI got 403 and WebFetch 402, but `curl -A "Mozilla/5.0" "<wiki>/wiki/<Page>?action=raw"` returned clean wikitext instantly (the same `?action=raw` trick as the Wikisource lesson above -- it works on any MediaWiki host, even when the api.php TextExtracts route is absent).

- **A paywalled DOI gets the three-probe recovery before anyone buys or gives up: Unpaywall, then the Wayback copy of the publisher's OLD fulltext URL, then PMC.** `api.unpaywall.org/v2/<DOI>?email=<any>` lists every registered OA location -- including files the abstract page never links (one supplement lived behind an unlabeled `links.lww.com` shortlink). Platform migrations strand full text the live site no longer serves; when `archive.org/wayback/available` misses, search the CDX index (`web.archive.org/cdx/search/cdx?url=<journal-fulltext-path>*&collapse=urlkey`) -- the snapshot can sit under a different URL suffix than the live page. Bank the extraction in `raw/` with a provenance header (snapshot date, route), and **anchor each quote to the artifact that carries it** -- extractors drop blocks (an abstract, a table), and a span absent from the banked text is unverifiable there no matter how "verbatim" it is. 

- **Re-run `check_raw.py` at close-out, not only when the user announces new files.** Step 3 assumes drops are announced; often they are not -- files land while you are writing pages. Know the tell: a trailing **"Still pending: N added"** after `--accept` does NOT mean the acceptance failed, it means *new* files arrived mid-session. Detect again before writing the log entry. 

- **Reconcile what you ingested against what the detector reported -- a source the detector never listed is a detector bug, not a bookkeeping footnote.** Step 2 says accept *exactly what was ingested*, and that only works if the detector saw it. If you finish a source and then cannot accept it because `check_raw.py` never listed it, stop and find out why the scan missed it, instead of noting the gap in `log.md` and moving on. The detector defines what counts as a source, so anything it structurally cannot see is invisible to the entire loop -- never detected, never baselined, and it will not flag when it changes. 

- **Instrument-generated numbers carry error the file never states -- check it before a figure hardens into a page.** A GPX/CSV/sensor export *looks* like data, so its numbers get copied as fact and then propagate into *derived* figures that drive decisions. Compare the instrument's noise floor against its sampling rate before quoting anything. 

  **The same floor applies to *quantization*, and that is where an apparent "conflict" usually lives.** When two documents for the same thing disagree, compute the rounding resolution of the underlying measurement *before* treating the gap as a finding, and adjudicate with an **independent third reference** rather than trusting whichever document arrived most recently or looks most primary. A newer photo is not automatically better data. 

- **Transcript-derived sources use the fleet provenance contract.** Require `source_file:`, canonical `transcript_kind:`, and a literal `## Locators` section whose entries pair timestamp + verbatim words; source links use a `#heading` anchor. Preserve `/watch`'s kind-valued `transcript_source:` verbatim -- never put a path there. MACHINE kinds (`auto-captions`, `whisper-local`, `whisper-remote`) need frame/audio verification for load-bearing claims or `==unverified==`; label their direct quotes *(machine transcript)*. Full mapping, fallback, and tier rules: `_meta/fleet-conventions.md` (Transcript-derived sources).

- **When a source belongs to a set, compare it against the others -- the finding is often in the comparison, not in any single file.** Serial per-source ingest is blind to relationships that exist only across files. Run the cheap pairwise comparison and record the non-matches as well as the matches. 

- **Write up rejected coincidences, not just accepted findings.** A seductive near-match you correctly dismiss gets rediscovered by a later session and mistaken for confirmation unless the rejection is on the page. 

- **Ingesting from a derived corpus (another wiki, a summary, your own old notes) is not ingesting from a source -- treat every page as a claim to verify.** Read the primary source and let it win. Four fabrication classes worth checking by name: **fabricated citations** (real authors, plausible years, papers the corpus does not hold); **personal notes in citation position** (`"Personal note: author, date"` carrying a load-bearing claim); **in-vitro laundered into human prescription** (a ">=6 h between loading bouts" rule traced to an engineered-tendon-construct protocol); and **fabricated precision** (week-by-week grids attributed to an author who gives only a floor and a graduation criterion). Two symmetry warnings: the error runs **both** ways -- an agent also wrongly declared a claim unsourced that the primary paper supported verbatim, so verify rather than assume in either direction -- and **your own relay is not exempt**: a fabricated figure reached a live page via the orchestrator's own briefing note, copied from the migration plan instead of the paper.

- **AI-generated `[wisdom]` / summary extracts misquote the transcripts they summarize -- quote the transcript, never the extract.** A source often arrives as several variants (`[topics]` AI-headered transcript, `[wisdom]` AI-extracted summary, raw transcript). Treat them as one ingest, but treat only the transcript as quotable: the extract is a navigation aid, not evidence. Cross-check every line you intend to put inside a `> [!quote]`. 

  **The distinction that makes this actionable:** `[topics]` is the speaker's own words with headers added -- lossless, so quotable once you check the header hasn't relabelled the content. `[wisdom]` is a paraphrase that *replaces* the source -- never quotable, at any confidence. If you control the extraction tool, the fix is to **make it emit an index, not a summary**: timestamps or line numbers pointing at the passages worth reading, with a few words of label. An index sends you to the source; a summary competes with the source and eventually wins, because it is shorter and reads more confidently than the hedged original. It is also cheap to verify, which a summary never is.

- **PDF extraction order is not reading order -- in a two-column layout or a table, a fluent "verbatim" quote can be text that never existed.** Full-width extraction interleaves columns into invented sentences, and table extraction emits cell blocks column-by-column, so a reassembled row is a splice, not a quote. Detect the gutter per page (word `x0` gaps) and re-extract per column before quoting; never rebuild a table row inside `> [!quote]` -- transcribe it into a Markdown table instead. Flag on the page any quote that legitimately spans a column or page break, since it will never appear contiguously and a verifier will otherwise false-flag it. 

- **A pass that both finds drift and drafts the fix has no check on its own prose -- refute the fix, not just the finding.** The adversarial step already in this file attacks *claims*; add one that attacks your *replacement wording*, because the agent that diagnosed a defect is the worst judge of the sentence it just wrote. 

- **Fixing a `sources/` page does not fix the pages that cite it -- sweep both directions in the same session.** A corrected source page sitting beside stale citations is worse than an obvious error, because it reads as verified. 

- **Sizing a link-health job: measure the *live* set, and know what actually resolves.** Two traps, each of which produced a wrong answer on 2026-07-28. **(a)** Obsidian resolves a wikilink by **filename stem only -- never by `title:`, and not by frontmatter `aliases`** (a bare `[[alias]]` is grey; regression R151). `lint.py` still matches aliases, but only to report them under ALIAS-ONLY -- they are not resolved links. A script that treats a matching title as "resolves" will hide whole files from its own output and undercount the fix by hundreds; read `lint.py`'s resolution code rather than guessing at it. **(b)** A raw broken-link count includes `log.md`, which is append-only -- its links correctly point at pages that existed when the entry was written, so counting them reports history as damage. One vault's headline was **521 broken links**; the live-page share was **272**, of which 249 were mechanically fixable to `[[kebab|Display]]` and the remaining 23 were intentional grey nodes (unresolved links are deliberate -- see CLAUDE.md). **Split history from live before estimating, and never sweep `log.md`.**

- **Harvest before you delete -- and do not let page length stand in for completeness.** When consolidating or migrating, verify what the doomed page holds *against the primary* before removing it. 

- **Preserve heading-anchor characters verbatim.** Do not replace an em-dash with two hyphens or otherwise rewrite a heading inside an anchor. If a configured editor cannot preserve a heading, use a unique ASCII block ID on the cited paragraph, then cite `#^block-id|display`. Check for collisions first; never edit generated pages to add an ID. Verify the link in Obsidian. No ASCII write guard is bundled with this template.

- **An "observation" you can state precisely is a verdict you are declining to write down. Grade it DRIFTED and fix it in the same step.** The claim audit offers four verdicts, and there is a strong pull toward marking a small discrepancy FAITHFUL-with-a-note rather than DRIFTED -- the claim *is* substantively right, the gap *is* minor, and the note feels like diligence. It is the opposite. A log entry reading FAITHFUL is what the next session greps, and it certifies the page as checked; the note underneath it is prose nobody re-reads. **If you can quote the source and quote the wiki and say exactly how they differ, you have done the whole diagnosis -- stopping short of the verdict just launders the defect as verified.** 

  **Do not rewrite a cell from an excerpt.** Read the complete primary sentence, including any continuation. Preserve both omitted clauses and qualifiers when correcting the claim.

- **Closing a ledger entry: anchor the edit to the `-- trigger:` date, not to the bolded opener.** Open-loops entries are one long line -- bolded title, then several sentences of reasoning, then the trigger. An Edit whose `old_string` matches only the title flips the checkbox and **leaves the entire body, including a live trigger date, attached to a now-`[x]` line**. Worse than nagging, the result is **silence**: `check_stale.py` never surfaces an `[x]` line again (section A filters to open statuses before the overdue check, section B excludes the ledger file and skips `[x]` lines everywhere else), so the stale reasoning survives as if current with no scanner left to catch it. The tell is the count: closing one loop and opening two should move 32 -> 33, not 32 -> 34. **Check `grep -n "trigger: <date>"` after any closure**, and either fold the reasoning worth keeping into the new closed line or delete it outright. 

- **A screen-captured ebook is an image-only source whose locator is the reader-app footer -- verify the capture geometry BEFORE ingesting, and re-render every screen you quote from.** Three sub-rules: (a) `completed: true` proves only `frames_written == pages_requested`, where `pages_requested` is the user-supplied count. A missing or incomplete manifest is unfinished, but a completed one still requires checking that footer counters form the expected `1/y` through `y/y` sequence (mechanical: `python scripts/verify_capture.py <run dirs, in capture order> --out-dir <temp dir>` -- counters, cross-run duplicates, junk frames, manifest; regression R49) and inspecting the first, last, and a middle frame for clipped text -- keyword indexing cannot catch a crop because there is no text layer (capture usage: the script's own header, `python scripts/help.py screen_capture`); (b) cite by screen file + footer + nearest section heading (`page_010.png, ch.2 screen 3/5, "The Long Run"`) -- the footer stands in for the print page number, so it must stay in frame, and footers reflow with font size and window geometry, so the heading is the part of the locator that survives a recapture; (c) a subagent's transcription of a screen is an excerpt, not verification -- before publishing, re-render the exact screens behind every `> [!quote]` span in the ingesting session and mark everything else *(agent-transcribed)* on the source page, so the next session knows which quotes are load-bearing-safe. 

- **Swarm fan-out over captured screens: slice on page ranges with a one-screen overlap at every cut, and give the on-screen footer authority over the slice prompt.** The orchestrator slices before anyone has read a screen, so the slice prompts' chapter labels are guesses -- each reader returns a verbatim per-screen footer map and reports prompt-vs-actual mismatches instead of force-fitting its slice. At swarm scale, rule (c) above is discharged by a refutation wave: after the sources page is drafted, fresh agents re-read the exact named screens themselves (never transcripts) trying to REFUTE each quote that landed on the page -- a quote that survives the wave counts as re-render-verified rather than *(agent-transcribed)*, and quotes the wave did not cover keep the marker. 

- **Parallel capture agents share one scratchpad -- isolate every worker's output paths, and verify quotes against an extraction the same agent just made.** The scratchpad directory is session-scoped, not agent-scoped, so `extract.py`, `verify.py`, and `<author>.json` collide across a fan-out; the symptom is a sibling's paper coming back for your own file, which can be misdiagnosed as tool fabrication. Before launching workers, the coordinator assigns distinct source slugs (even for papers by the same author) and pins each worker's output namespace in its prompt. Single-worker sources may use `<slug>_<step>.*`. When multiple workers operate on the same source, each MUST have a coordinator-assigned unique worker/slice identifier and use `<slug>_<worker-or-slice>_<step>.*`, or its own dedicated worker directory. Prefer deterministic slice IDs or page/frame ranges over arbitrary agent names: screen-slicing workers could write `hansons_p001-080_extract.json` and `hansons_p080-160_extract.json`, preserving the one-screen overlap without sharing a file. Apply the isolation to scripts, extracted text, renders, and every other temporary artifact; workers must never share an output path or independently invent their identifiers. Re-extract the assigned primary immediately before the final quote check; a verification count computed against a sibling's or stale extraction is not a verification. This applies to both hand-fanned `Agent` calls and Workflow swarms. 

- **Write backslash-bearing content with a file-editing tool**, never a Bash heredoc when shell interpolation or wrappers could transform it. For multiline CLI text, create a file and use `--body-file`. Verify the saved bytes. This is a portability precaution; no shell hook is bundled here.
